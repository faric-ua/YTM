## Approved Home direction

The supplied prototype is a **layout / hierarchy reference only**.

R1 keeps the existing YTM Importer visual language and all three palettes:
- Neon Dark;
- Blue Dark;
- Green Dark.

R1 does **not** copy the prototype's yellow/blue palette, embroidery, photos,
branding or ornamental button style.

The approved Home hierarchy is:

1. compact header;
2. `4 кроки до плейлиста`;
3. utility row: History / Queue / Quota / Menu;
4. account/status block;
5. `Поточний плейлист`;
6. `Швидкі дії`;
7. fixed bottom navigation: Home / Search / Playlist / Service.

The main dashboard content is scrollable so landscape does not hide the account,
playlist or quick-action sections.

## BUG-014 — custom modal chrome is only partially theme-aware

v1.4.47 phone evidence:
- dialog titles followed the selected theme;
- dialog/card/button surfaces and some action colors stayed on hardcoded Neon-like
  values after switching to Green/Blue.

R1:
- message text uses the active palette;
- dialog surface / row surface / border use the active palette;
- normal actions use palette text;
- accent actions use palette accent;
- destructive actions intentionally remain semantic danger/red.

## BUG-015 — delegated Playlist-Hub actions lose their parent

v1.4.47 phone evidence:
- Search/Create actions closed PlaylistActivity before delegating into MainActivity;
- Back/Cancel could therefore return to Home instead of Playlist Hub.

R1:
- Main remembers when Search/Create originated from Playlist Hub;
- canceled Review/Destination returns reopen Playlist Hub;
- canceling the Search-plan modal reopens Playlist Hub;
- completed write result actions return to Playlist Hub when the write originated there.

Problem/link actions no longer need to leave PlaylistActivity:
- replacement/problem dialog is owned directly by PlaylistActivity;
- Open in YTM and Copy link execute directly from PlaylistActivity.

## BUG-016 — modal state lost on rotation

v1.4.47 phone evidence reproduced the problem/replacement dialog disappearing after
rotation.

R1:
- PlaylistActivity persists the replacement-dialog open state;
- the dialog is rebuilt after Activity recreation;
- ImportActivity also persists the destructive `Очистити поточний список?`
  confirmation because that modal was part of the same phone-test surface.

## BUG-017 — Home landscape hides lower dashboard sections

v1.4.47 landscape phone evidence showed the workflow and utility row but pushed the
account/current-playlist dashboard below the visible viewport.

R1:
- Home dashboard body is inside a ScrollView;
- bottom navigation remains outside the scrollable body;
- account, current playlist and quick actions remain reachable in landscape.

## Architecture

- auth/search/write semantics are not intentionally changed.
