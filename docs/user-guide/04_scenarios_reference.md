# 21. Практичні сценарії
<a id="sec21"></a>
## Сценарій 1 — створити новий плейлист із CSV
<a id="sec21a"></a>
1. Home → 1. Імпорт → Вибрати файл → вибрати CSV.
2. Home → 2. Google / YTM → підключити акаунт.
3. Home → 3. Знайти / перевірити → переглянути Search plan → Почати.
4. У Review виправити жовті/проблемні позиції, за потреби використати ручний URL.
5. Далі → Створити / додати → ввести назву і приватність.
6. Підтвердити write, переглянути результат і History.

## Сценарій 2 — додати треки до існуючого плейлиста без дублікатів
<a id="sec21b"></a>
1. Імпортувати або відновити потрібний локальний список.
2. Перевірити треки в Review.
3. Створити / додати → Вибрати існуючий плейлист.
4. Вибрати ціль і дочекатися duplicate check.
5. Обрати «Пропустити дублікати й додати».
6. Після завершення перевірити History та remote playlist.

## Сценарій 3 — роботу зупинив rate limit
<a id="sec21c"></a>
1. Не натискати write багато разів поспіль.
2. Відкрити Queue або ⚠ Recovery Center.
3. Переглянути причину паузи та remaining tracks.
4. Після певного часу відкрити job і явно натиснути «Продовжити».
5. Якщо потрібен інший акаунт — спочатку переключити його на Home.

## Сценарій 4 — відновити стару роботу з History
<a id="sec21d"></a>
1. History → знайти потрібний логічний плейлист.
2. Відкрити операцію → «Відновити як поточний плейлист».
3. Підтвердити локальну заміну current workspace.
4. Перевірити Review/Playlist Hub.
5. Search або write запускати окремо лише якщо вони справді потрібні.

## Сценарій 5 — зробити страховку перед експериментом
<a id="sec21e"></a>
1. Меню → Дані → Повна резервна копія → Зберегти копію.
2. Переконатися, що файл записано.
3. Виконати потрібні локальні дії.
4. Якщо локальний стан зіпсований — Restore із backup; перед Restore застосунок сам створить safety snapshot.
5. За потреби використати «Відкотити останнє відновлення».

## Сценарій 6 — архівувати бібліотеку акаунта
<a id="sec21f"></a>
1. Імпорт → Експортувати всі плейлисти в папку або вибрати конкретні.
2. Вибрати папку parent через Storage Chooser.
3. Дочекатися read-only export YTM Project + manifest.
4. Для наступного оновлення використати «Оновити backup (incremental)».
5. Періодично створювати зведений Full Backup з delta-ланцюжка.

# 22. Типові проблеми та що робити
<a id="sec22"></a>
| Симптом | Що робити |
| --- | --- |
| Google/YTM більше не дійсний / HTTP 401 | Home → 2. Google / YTM → підключити акаунт знову. Локальний workspace не повинен зникнути. |
| Search quota закінчилась | Перевірити Queue. Cached треки можуть бути оброблені, решта зберігається як відновлюване завдання. |
| Write зупинено “забагато запитів” | Не повторювати write багато разів. Зачекати й явно продовжити через Queue. |
| Не той JSON у Restore | Скористатися основним списком потрібного типу або «Інший файл…». Owner validator повинен відхилити неправильний формат без мутації. |
| Плейлист порожній / відео недоступне | Перевірити, чи remote playlist містить доступні відео. Private/deleted відео можуть бути позначені як unavailable. |
| У existing playlist є дублікати | Використати duplicate check і «Пропустити дублікати». Порівняння йде за exact videoId. |
| Не можу знайти backup у списку останніх файлів | Надати доступ до Download, додати SAF-папку або використати «Інший файл… / Системний вибір…». |
| Не встановлюється оновлення APK | Service → Версія; дати Android дозвіл на встановлення з YTM Importer, повернутися і повторити «Встановити». |
| Bulk Sync не створює нову сесію | Можливо, вже є незавершена сесія. Відкрити «Поточна синхронізація всіх» або Recovery Center. |
| Після rotation “щось мало запуститися” | Ні. Rotation відновлює UI/state, але не повинен сам запускати remote операції. |

# 23. Статуси та умовні позначення
<a id="sec23"></a>
## Review / Track
<a id="sec23a"></a>
| Статус | Сенс |
| --- | --- |
| Новий | ще не перевірений |
| Пошук | обробляється Search/Cache |
| Готовий | можна записувати |
| Потрібна перевірка | є кандидат, але потрібна ручна увага |
| Не знайдено | немає прийнятного кандидата |
| Пропущено | користувач свідомо не записує трек |
| Дублікат | повтор / уже є в цільовому плейлисті |
| Черга / Очікує квоту | потрібне явне продовження пізніше |
| Додано | remote write успішний |
| Помилка | write/Search завершився з проблемою |

## History / Pending
<a id="sec23b"></a>
| Статус | Сенс |
| --- | --- |
| Виконується | операція ще активна |
| Завершено | успішний terminal state |
| Частково / очікує продовження | є виконана частина і залишок |
| Очікує квоти | пауза до відновлення quota |
| Пауза через ліміт API | тимчасове rate/service обмеження |
| Помилка | операція не завершилась успішно |

## Bulk Session
<a id="sec23c"></a>
- Попередній перегляд / Готово до запуску / Виконується.
- Пауза — ліміт пошуку / квота запису / тимчасовий API limit / потрібна авторизація / попередню синхронізацію перервано.
- Завершено / Частково завершено з помилкою.
- Виконується відкат / Відкат на паузі / Відкочено.

# 24. Глосарій і коротка шпаргалка
<a id="sec24"></a>
| Термін | Простими словами |
| --- | --- |
| videoId | Точний ID конкретного YouTube відео. Ключовий для duplicate check і точного відновлення. |
| playlistId | Точний ID YouTube/YTM плейлиста. |
| playlistItemId | ID конкретного елемента всередині remote playlist; потрібний для exact rollback. |
| YTM Project | Переносний робочий проєкт одного плейлиста з треками та match/videoId. |
| SearchCache | Локальний кеш результатів пошуку, що економить search quota. |
| Pending Queue | Відновлювані Search/write job, що зупинилися. |
| History | Локальний журнал завершених/часткових операцій. |
| Recovery Center | Індекс станів, які потребують уваги; сам нічого не виконує. |
| Bulk Sync | Масовий workflow: preview → durable session → explicit write → optional exact rollback. |
| Remote baseline | Snapshot фактичного remote стану, прочитаний перед/під час Bulk Sync. |
| Safety snapshot | Локальна страховка перед Restore/History import, з якої можна відкотити локальний стан. |
| manifest.json | Індекс account-library backup папки з посиланнями на YTM Project файли. |
| SAF | Android Storage Access Framework — системний механізм вибору папок/файлів із запам’ятовуваним доступом. |
