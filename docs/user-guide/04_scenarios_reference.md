# 21. Практичні сценарії
<a id="sec21"></a>
## Сценарій 1 — створити новий плейлист із CSV
<a id="sec21a"></a>
1. Головний екран → 1. Імпорт → Вибрати файл → вибрати CSV.
2. Головний екран → 2. Google / YTM → підключити акаунт.
3. Головний екран → 3. Знайти / перевірити → переглянути план пошуку → Почати.
4. У Перевірка виправити жовті/проблемні позиції, за потреби використати ручний URL.
5. Далі → Створити / додати → ввести назву і приватність.
6. Підтвердити запис, переглянути результат і Історія.

## Сценарій 2 — додати треки до існуючого плейлиста без дублікатів
<a id="sec21b"></a>
1. Імпортувати або відновити потрібний локальний список.
2. Перевірити треки в Перевірка.
3. Створити / додати → Вибрати існуючий плейлист.
4. Вибрати ціль і дочекатися перевірка дублікатів.
5. Обрати «Пропустити дублікати й додати».
6. Після завершення перевірити Історія та віддалений плейлист.

## Сценарій 3 — роботу зупинив rate limit
<a id="sec21c"></a>
1. Не натискати запис багато разів поспіль.
2. Відкрити Черга або ⚠ Центр відновлення.
3. Переглянути причину паузи та remaining tracks.
4. Після певного часу відкрити job і явно натиснути «Продовжити».
5. Якщо потрібен інший акаунт — спочатку переключити його на Головний екран.

## Сценарій 4 — відновити стару роботу з Історія
<a id="sec21d"></a>
1. Історія → знайти потрібний логічний плейлист.
2. Відкрити операцію → «Відновити як поточний плейлист».
3. Підтвердити локальну заміну поточний робочий простір.
4. Перевірити Перевірка/центр поточного плейлиста.
5. пошук або запис запускати окремо лише якщо вони справді потрібні.

## Сценарій 5 — зробити страховку перед експериментом
<a id="sec21e"></a>
1. Меню → Дані → Повна резервна копія → Зберегти копію.
2. Переконатися, що файл записано.
3. Виконати потрібні локальні дії.
4. Якщо локальний стан зіпсований — Restore із резервна копія; перед Restore застосунок сам створить safety знімок.
5. За потреби використати «Відкотити останнє відновлення».

## Сценарій 6 — архівувати бібліотеку акаунта
<a id="sec21f"></a>
1. Імпорт → Експортувати всі плейлисти в папку або вибрати конкретні.
2. Вибрати папку батьківську папку через екран вибору папки.
3. Дочекатися лише для читання export Проєкт YTM + manifest.
4. Для наступного оновлення використати «Оновити резервну копію (інкрементно)».
5. Періодично створювати зведений повна резервна копія з дельта-ланцюжка.

# 22. Типові проблеми та що робити
<a id="sec22"></a>
| Симптом | Що робити |
| --- | --- |
| Google/YTM більше не дійсний / HTTP 401 | Головний екран → 2. Google / YTM → підключити акаунт знову. Локальний робочий простір не повинен зникнути. |
| Пошук квота закінчилась | Перевірити Черга. Кешовані треки можуть бути оброблені, решта зберігається як відновлюване завдання. |
| Write зупинено “забагато запитів” | Не повторювати запис багато разів. Зачекати й явно продовжити через Черга. |
| Не той JSON у Restore | Скористатися основним списком потрібного типу або «Інший файл…». Owner validator повинен відхилити неправильний формат без мутації. |
| Плейлист порожній / відео недоступне | Перевірити, чи віддалений плейлист містить доступні відео. Приватні або видалені відео можуть бути позначені як недоступні. |
| У існуючому плейлисті є дублікати | Використати перевірка дублікатів і «Пропустити дублікати». Порівняння йде за точний `videoId`. |
| Не можу знайти резервна копія у списку останніх файлів | Надати доступ до Download, додати SAF-папку або використати «Інший файл… / Системний вибір…». |
| Не встановлюється оновлення APK | Сервіс → Версія; дати Android дозвіл на встановлення з YTM Імпортer, повернутися і повторити «Встановити». |
| Синхронізація всіх не створює нову сесію | Можливо, вже є незавершена сесія. Відкрити «Поточна синхронізація всіх» або Центр відновлення. |
| Після поворот екрана “щось мало запуститися” | Ні. Rotation відновлює інтерфейс і стан, але не повинен сам запускати віддалені операції. |

# 23. Статуси та умовні позначення
<a id="sec23"></a>
## Перевірка / Track
<a id="sec23a"></a>
| Статус | Сенс |
| --- | --- |
| Новий | ще не перевірений |
| Пошук | обробляється пошуком або кешем |
| Готовий | можна записувати |
| Потрібна перевірка | є кандидат, але потрібна ручна увага |
| Не знайдено | немає прийнятного кандидата |
| Пропущено | користувач свідомо не записує трек |
| Дублікат | повтор / уже є в цільовому плейлисті |
| Черга / Очікує квоту | потрібне явне продовження пізніше |
| Додано | віддалений запис успішний |
| Помилка | запис/Пошук завершився з проблемою |

## Історія / Pending
<a id="sec23b"></a>
| Статус | Сенс |
| --- | --- |
| Виконується | операція ще активна |
| Завершено | успішний кінцевий стан |
| Частково / очікує продовження | є виконана частина і залишок |
| Очікує квоти | пауза до відновлення квота |
| Пауза через ліміт API | тимчасове частотне або сервісне обмеження |
| Помилка | операція не завершилась успішно |

## Сесія синхронізації
<a id="sec23c"></a>
- Попередній перегляд / Готово до запуску / Виконується.
- Пауза — ліміт пошуку / квота запису / тимчасовий ліміт API / потрібна авторизація / попередню синхронізацію перервано.
- Завершено / Частково завершено з помилкою.
- Виконується відкат / Відкат на паузі / Відкочено.

# 24. Глосарій і коротка шпаргалка
<a id="sec24"></a>
| Термін | Простими словами |
| --- | --- |
| `videoId` | Точний ID конкретного YouTube відео. Ключовий для перевірка дублікатів і точного відновлення. |
| playlistId | Точний ID YouTube/YTM плейлиста. |
| playlistItemId | ID конкретного елемента всередині віддалений плейлист; потрібний для точний відкат. |
| Проєкт YTM | Переносний робочий проєкт одного плейлиста з треками та match/`videoId`. |
| кеш пошуку | Локальний кеш результатів пошуку, що економить search квота. |
| Pending Черга | Відновлювані Пошук/запис job, що зупинилися. |
| Історія | Локальний журнал завершених/часткових операцій. |
| Центр відновлення | Індекс станів, які потребують уваги; сам нічого не виконує. |
| Синхронізація всіх | Масовий сценарій: попередній перегляд → durable session → explicit запис → optional точний відкат. |
| Віддалений базовий стан | Snapshot фактичного remote стану, прочитаний перед/під час Синхронізація всіх. |
| Safety знімок | Локальна страховка перед Restore/імпорту Історії, з якої можна відкотити локальний стан. |
| `manifest.json` | Індекс резервна копія бібліотеки акаунта папки з посиланнями на файли Проєкту YTM. |
| SAF | системний механізм Android для доступу до сховища — системний механізм вибору папок/файлів із запам’ятовуваним доступом. |
