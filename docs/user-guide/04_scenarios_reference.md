# 21. Практичні сценарії
<a id="sec21"></a>
## Сценарій 1 — створити новий плейлист із CSV
<a id="sec21a"></a>
1. Головний екран → 1. Імпорт → Вибрати файл → вибрати CSV.
2. Головний екран → 2. Google / YTM → підключити акаунт.
3. Головний екран → 3. Знайти / перевірити → переглянути план пошуку → Почати.
4. На екрані перевірки виправити жовті/проблемні позиції, за потреби використати ручний URL.
5. Далі → Створити / додати → ввести назву і приватність.
6. Підтвердити запис, переглянути результат та запис в Історії.

## Сценарій 2 — додати треки до існуючого плейлиста без дублікатів
<a id="sec21b"></a>
1. Імпортувати або відновити потрібний локальний список.
2. Перевірити треки на екрані перевірки.
3. Створити / додати → Вибрати існуючий плейлист.
4. Вибрати ціль і дочекатися перевірки дублікатів.
5. Обрати «Пропустити дублікати й додати».
6. Після завершення перевірити Історію та віддалений плейлист.

## Сценарій 3 — роботу зупинило обмеження частоти запитів
<a id="sec21c"></a>
1. Не натискати запис багато разів поспіль.
2. Відкрити Чергу або ⚠ Центр відновлення.
3. Переглянути причину паузи та треки, що залишилися.
4. Після певного часу відкрити завдання і явно натиснути «Продовжити».
5. Якщо потрібен інший акаунт — спочатку переключити його на головному екрані.

## Сценарій 4 — відновити стару роботу з Історії
<a id="sec21d"></a>
1. Історія → знайти потрібний логічний плейлист.
2. Відкрити операцію → «Відновити як поточний плейлист».
3. Підтвердити локальну заміну поточного робочого простору.
4. Перевірити стан на екрані перевірки або в центрі поточного плейлиста.
5. Пошук або запис запускати окремо лише якщо вони справді потрібні.

## Сценарій 5 — зробити страховку перед експериментом
<a id="sec21e"></a>
1. Меню → Дані → Повна резервна копія → Зберегти копію.
2. Переконатися, що файл записано.
3. Виконати потрібні локальні дії.
4. Якщо локальний стан зіпсований — відновлення з резервної копії; перед відновленням застосунок сам створить страхувальний знімок.
5. За потреби використати «Відкотити останнє відновлення».

## Сценарій 6 — архівувати бібліотеку акаунта
<a id="sec21f"></a>
1. Імпорт → Експортувати всі плейлисти в папку або вибрати конкретні.
2. Вибрати батьківську папку через екран вибору папки для збереження.
3. Дочекатися завершення експорту в режимі лише читання: файли Проєкту YTM та маніфест.
4. Для наступного оновлення використати «Оновити резервну копію (інкрементно)».
5. Періодично створювати зведену повну резервну копію з дельта-ланцюжка.

# 22. Типові проблеми та що робити
<a id="sec22"></a>
| Симптом | Що робити |
| --- | --- |
| Google/YTM більше не дійсний / HTTP 401 | Головний екран → 2. Google / YTM → підключити акаунт знову. Локальний робочий простір не повинен зникнути. |
| Закінчилась квота пошуку | Перевірити Чергу. Треки з кешу можуть бути оброблені, решта зберігається як відновлюване завдання. |
| Запис зупинено: «забагато запитів» | Не повторювати запис багато разів. Зачекати й явно продовжити через Чергу. |
| Не той JSON у відновленні | Скористатися основним списком потрібного типу або «Інший файл…». Перевірка формату повинна відхилити неправильний файл без зміни даних. |
| Плейлист порожній / відео недоступне | Перевірити, чи віддалений плейлист містить доступні відео. Приватні або видалені відео можуть бути позначені як недоступні. |
| В існуючому плейлисті є дублікати | Використати перевірку дублікатів і «Пропустити дублікати». Порівняння виконується за точним `videoId`. |
| Не можу знайти резервну копію у списку останніх файлів | Надати доступ до Download, додати SAF-папку або використати «Інший файл… / Системний вибір…». |
| Не встановлюється оновлення APK | Сервіс → Версія; дати Android дозвіл на встановлення з YTM Importer, повернутися і повторити «Встановити». |
| Синхронізація всіх не створює нову сесію | Можливо, вже є незавершена сесія. Відкрити «Поточна синхронізація всіх» або Центр відновлення. |
| Після повороту екрана «щось мало запуститися» | Ні. Поворот екрана відновлює інтерфейс і стан, але не повинен сам запускати віддалені операції. |

# 23. Статуси та умовні позначення
<a id="sec23"></a>
## Перевірка / трек
<a id="sec23a"></a>
| Статус | Сенс |
| --- | --- |
| Новий | ще не перевірений |
| Пошук | обробляється пошуком або кешем |
| Готовий | можна записувати |
| Потрібна перевірка | є кандидат, але потрібна ручна увага |
| Не знайдено | немає прийнятного кандидата |
| Пропущено | користувач свідомо не записує трек |
| Дублікат | повтор / уже є в цільовому плейлисті |
| Черга / Очікує квоту | потрібне явне продовження пізніше |
| Додано | віддалений запис успішний |
| Помилка | запис/пошук завершився з проблемою |

## Історія / Черга
<a id="sec23b"></a>
| Статус | Сенс |
| --- | --- |
| Виконується | операція ще активна |
| Завершено | успішний кінцевий стан |
| Частково / очікує продовження | є виконана частина і залишок |
| Очікує квоти | пауза до відновлення квоти |
| Пауза через ліміт API | тимчасове обмеження частоти / сервісне обмеження |
| Помилка | операція не завершилась успішно |

## Сесія синхронізації
<a id="sec23c"></a>
- Попередній перегляд / Готово до запуску / Виконується.
- Пауза — ліміт пошуку / квота запису / тимчасовий ліміт API / потрібна авторизація / попередню синхронізацію перервано.
- Завершено / Частково завершено з помилкою.
- Виконується відкат / Відкат на паузі / Відкочено.

# 24. Глосарій і коротка шпаргалка
<a id="sec24"></a>
| Термін | Простими словами |
| --- | --- |
| `videoId` | Точний ID конкретного відео YouTube. Ключовий для перевірки дублікатів і точного відновлення. |
| `playlistId` | Точний ID плейлиста YouTube/YTM. |
| `playlistItemId` | ID конкретного елемента всередині віддаленого плейлиста; потрібний для точного відкату. |
| Проєкт YTM | Переносний робочий проєкт одного плейлиста з треками та збереженими результатами зіставлення (`videoId`). |
| Кеш пошуку | Локальний кеш результатів пошуку, що економить квоту пошуку. |
| Черга незавершених операцій | Відновлювані завдання пошуку/запису, що зупинилися. |
| Історія | Локальний журнал завершених/часткових операцій. |
| Центр відновлення | Індекс станів, які потребують уваги; сам нічого не виконує. |
| Синхронізація всіх | Масовий сценарій: попередній перегляд → збережена сесія → явний запис → за потреби точний відкат. |
| Віддалений базовий стан | Знімок фактичного віддаленого стану, прочитаний перед або під час «Синхронізації всіх». |
| Страхувальний знімок | Локальна страховка перед відновленням або імпортом Історії, з якої можна відкотити локальний стан. |
| `manifest.json` | Індекс папки резервної копії бібліотеки акаунта з посиланнями на файли Проєкту YTM. |
| SAF | Системний механізм Android для вибору папок і файлів із можливістю запам’ятати наданий доступ. |
