# 1. Що таке YTM Importer
<a id="sec01"></a>
YTM Importer — Android-застосунок, який перетворює трекліст на керований робочий проєкт, допомагає знайти точні YouTube videoId, дозволяє вручну перевірити сумнівні результати, а потім створити новий плейлист або додати треки до вже існуючого YouTube / YouTube Music плейлиста.

## Основні можливості
<a id="sec01a"></a>
- Імпорт CSV, TXT, вставленого тексту та YTM Project.
- Read-only імпорт плейлиста з підключеного YouTube/YTM акаунта з точними videoId.
- Імпорт / snapshot плейлиста за URL із локальним preview перед збереженням.
- Планування пошуку, SearchCache і локальна оцінка квоти.
- Review кожного треку, вибір кандидата, ручне YouTube/YTM посилання, пропуск проблемного треку.
- Створення нового YTM плейлиста або додавання до існуючого з duplicate check за exact videoId.
- Queue / Resume після quota/rate-limit/auth пауз.
- History з пошуком, фільтрами, групуванням і відновленням запису як поточного робочого списку.
- Recovery Center — єдиний екран незавершених/перерваних станів.
- Bulk Sync — read-only preview усіх локальних плейлистів, явна сесія синхронізації, checkpoint і exact rollback.
- Локальний Full Backup, History-only restore, safety snapshot і rollback локального Restore.
- Експорт всієї/вибраної бібліотеки акаунта у YTM Project + manifest, incremental backup і зведення delta-ланцюжка.
- Diagnostics, SearchCache cleanup, quota screen, themes, changelog та вбудований updater.

## Чого застосунок принципово не робить сам
<a id="sec01b"></a>
- Не запускає Search або write через rotation, Back або просте відкриття recovery-екрана.
- Не видаляє старий YouTube/YTM плейлист лише через збіг назви.
- Не вважає локальну оцінку quota точним балансом Google Cloud.
- Не зберігає OAuth access token у YTM Project, Diagnostics або Full Backup.
- Не має власного сервера, реклами чи вбудованої аналітики.

# 2. Швидкий старт: 4 кроки
<a id="sec02"></a>
*Основний користувацький шлях від трекліста до готового плейлиста.*

1. Імпорт. Отримайте локальний робочий список із CSV/TXT/YTM Project, вставленого тексту, плейлиста акаунта або URL snapshot.
2. Google / YTM. Підключіть Google-акаунт і переконайтесь, що YouTube/YTM канал визначено.
3. Знайти / перевірити. Запустіть пошук лише для треків, яким він потрібен, і вручну перевірте сумнівні результати.
4. Створити / додати. Створіть новий плейлист або виберіть існуючий, пройдіть duplicate check і явно підтвердьте запис.

> **Порада для першого запуску**  
> Почніть з невеликого трекліста на 3–10 позицій. Так простіше побачити весь цикл: імпорт → пошук → Review → duplicate check → write → History.

> **Не поспішайте з кроком 4**  
> Якщо у Review є статус «Потрібна перевірка», краще відкрити трек і перевірити версію: Original / Remix / Edit / Radio / Live можуть бути різними записами.

# 3. Головний екран Home
<a id="sec03"></a>
Home — центральна панель стану. Звідси доступні 4 основні кроки, History, Queue, Quota, Menu, картка акаунта, поточний плейлист і швидкі файлові дії.

*Реальний Home v1.4.55: 4 кроки, History/Queue/Quota/Menu, акаунт і поточний плейлист.*

## Верхня частина Home
<a id="sec03a"></a>
| Елемент | Призначення |
| --- | --- |
| ⚠ N біля версії | Компактний індикатор Recovery Center. З’являється лише коли є actionable стан. Після відкриття поточного count перестає “дихати”, доки count не зміниться. |
| 1. Імпорт | Відкриває всі способи отримання локального робочого списку. |
| 2. Google / YTM | Підключення або зміна Google-акаунта, показ профілю/каналу. |
| 3. Знайти / перевірити | План Search, запуск пошуку і перехід у Review. |
| 4. Створити / додати | Вибір нового або існуючого цільового плейлиста. |
| Історія | Логічна історія плейлистів і операцій. |
| Черга | Незавершені Search/write операції. |
| Квота | Локальна оцінка пошукової й загальної API-квоти. |
| Меню | Додаткові інструменти: тема, Bulk Sync, Recovery Center, Data, Service тощо. |

## Картка поточного плейлиста
<a id="sec03b"></a>
Показує назву, кількість треків і стислий стан: скільки готові, скільки треба перевірити, дублікати, черга та проблеми. Натискання відкриває Playlist Hub — керування поточним локальним плейлистом.

> **Автовідновлення**  
> Останній робочий список зберігається локально. Це зручно після перезапуску, але для кількох паралельних списків слід користуватися YTM Project файлами.

# 4. Google / YouTube Music акаунт
<a id="sec04"></a>
Крок 2 використовує Google OAuth і YouTube Data API. Після підключення застосунок отримує доступ, потрібний для читання акаунта/каналу, пошуку та явно запущених операцій із плейлистами.

## Що показує вікно акаунта
<a id="sec04a"></a>
- Статус Google-підключення.
- Маскований/відображуваний профіль Google.
- Назву YouTube/YTM каналу та Channel ID.
- Нагадування, що OAuth token у цьому вікні не показується й на диск не зберігається.

## Автоматичне відновлення сесії
<a id="sec04b"></a>
При старті YTM Importer може спробувати тихо відновити Google/YTM сесію без нового ручного входу. Якщо Google відхиляє авторизацію або повертається HTTP 401, застосунок скидає статус підключення, але локальний робочий список не видаляє.

> **Якщо бачите “потрібне повторне підключення”**  
> Поверніться на Home → «2. Google / YTM» → увійдіть знову. Незавершені write/Search операції, якщо вони вже були збережені, шукайте в Queue або Recovery Center.

## Зміна акаунта
<a id="sec04c"></a>
У вікні «Акаунт» є дія «Змінити». Якщо Pending job був створений для іншого каналу/акаунта, YTM Importer не повинен мовчки продовжувати його під іншим профілем — користувачу пропонується змінити акаунт або скасувати.

# 5. Імпорт: усі способи
<a id="sec05"></a>
*Усі основні джерела сходяться в один локальний «Поточний плейлист».*

## CSV, TXT або YTM Project
<a id="sec05a"></a>
«1. Імпорт» → «Імпорт із файлу» → «Вибрати файл». Системний picker приймає широкий MIME type, тому що деякі Android providers неправильно маркують CSV. Після вибору YTM Importer читає файл локально.

| Формат | Що отримуємо |
| --- | --- |
| CSV / TXT | Рядки трекліста. Далі треки зазвичай потребують Search/Review. |
| YTM Project | Повноцінний робочий проєкт. Exact videoId, якщо були збережені, не потребують нового search.list. |

## Вставити текст
<a id="sec05b"></a>
Можна вставити список прямо в поле. Один трек — один рядок у форматі «Artist - Track». Підтримуються різні тире ( -, – , — ) і нумерація на кшталт «1.» або «2)». Назва плейлиста необов’язкова.

## Read-only імпорт із акаунта YouTube/YTM
<a id="sec05c"></a>
«Плейлист з підключеного акаунта» завантажує список плейлистів, після вибору читає його треки й створює локальний робочий список уже з точними videoId. Віддалений плейлист при цьому не змінюється.

> **READ-ONLY**  
> Імпорт плейлиста з акаунта — лише читання. Він не додає, не видаляє й не переставляє треки у YouTube/YTM.

## Поточний робочий список
<a id="sec05d"></a>
На екрані Import видно автозбережений поточний список. Його можна очистити окремою явною дією. Очищення видаляє тільки локальний автозбережений workspace; YTM Project файли й віддалені YTM плейлисти не змінюються.

## Експорт плейлистів акаунта
<a id="sec05e"></a>
Import також містить інструменти для read-only експорту вибраних або всіх плейлистів акаунта. Вихід — папка з YTM Project файлами та manifest.json. Детально це описано в розділі 15.

# 6. URL Snapshot
<a id="sec06"></a>
«Імпорт за URL / Mix» відкриває окремий Snapshot-екран. Ви вставляєте URL плейлиста YouTube або YouTube Music, а читання починається тільки після «Прочитати URL».

## Що показує preview
<a id="sec06a"></a>
- Назву плейлиста, якщо її вдалося отримати.
- Загальну кількість елементів.
- Кількість унікальних exact videoId.
- Повторні входження exact videoId.
- Недоступні / private / deleted елементи.
- Діагностику джерела й resolver/cache.

Preview не змінює поточний робочий список. Search, Review і write також не запускаються автоматично.

## Повтори: усі чи унікальні
<a id="sec06b"></a>
Якщо знайдено повторні входження exact videoId, застосунок може запропонувати зберегти всі елементи або тільки унікальні. Це вибір локального snapshot, а не remote-редагування плейлиста.

## Локальний кеш URL snapshot
<a id="sec06c"></a>
Результат може читатися з локального cache. За потреби є явна дія «Оновити з YouTube». Для частини сценаріїв є окрема дія отримати назву плейлиста з API.

> **Mix**  
> Якщо resolver не підтримує конкретний Mix, застосунок прямо повідомить «Mix не підтримується цим resolver». Це не означає, що ваш локальний список пошкоджено.
