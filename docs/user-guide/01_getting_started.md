# 1. Що таке YTM Importer
<a id="sec01"></a>
YTM Importer — застосунок для Android, який перетворює трекліст на керований робочий проєкт, допомагає знайти точні ідентифікатори відео YouTube (`videoId`), дозволяє вручну перевірити сумнівні результати, а потім створити новий плейлист або додати треки до вже існуючого YouTube / YouTube Music плейлиста.

## Основні можливості
<a id="sec01a"></a>
- Імпорт CSV, TXT, вставленого тексту та файлів Проєкту YTM.
- Імпорт плейлиста з підключеного акаунта YouTube/YTM у режимі лише читання, зі збереженням точних `videoId`.
- Імпорт / знімок плейлиста за URL із локальним попереднім переглядом перед збереженням.
- Планування пошуку, кешування результатів пошуку та локальна оцінка квоти.
- Перевірка кожного треку, вибір кандидата, ручне YouTube/YTM посилання, пропуск проблемного треку.
- Створення нового плейлиста YTM або додавання до існуючого з перевіркою дублікатів за точним `videoId`.
- Черга та явне продовження після пауз через квоту, обмеження частоти запитів або авторизацію.
- Історія з пошуком, фільтрами, групуванням і відновленням запису як поточного робочого списку.
- Центр відновлення — єдиний екран незавершених/перерваних станів.
- Синхронізація всіх — попередній перегляд лише для читання, явна сесія синхронізації, контрольна точка та точний відкат.
- Локальна повна резервна копія, відновлення лише історії, страхувальний знімок і відкат локального відновлення.
- Експорт усієї або вибраної бібліотеки акаунта у форматі Проєкту YTM з маніфестом, інкрементне резервне копіювання та зведення дельта-ланцюжка.
- Діагностика, очищення кешу пошуку, екран квоти, теми, історія змін та вбудований модуль оновлення.

## Чого застосунок принципово не робить сам
<a id="sec01b"></a>
- Не запускає пошук або запис через поворот екрана, натискання «Назад» або просте відкриття екрана відновлення.
- Не видаляє старий YouTube/YTM плейлист лише через збіг назви.
- Не вважає локальну оцінку квоти точним балансом Google Cloud.
- Не зберігає токен доступу OAuth у Проєкті YTM, звіті діагностики або повній резервній копії.
- Не має власного сервера, реклами чи вбудованої аналітики.

# 2. Швидкий старт: 4 кроки
<a id="sec02"></a>
*Основний користувацький шлях від трекліста до готового плейлиста.*

1. Імпорт. Отримайте локальний робочий список із CSV/TXT/Проєкту YTM, вставленого тексту, плейлиста акаунта або знімка за URL.
2. Google / YTM. Підключіть Google-акаунт і переконайтесь, що YouTube/YTM канал визначено.
3. Знайти / перевірити. Запустіть пошук лише для треків, яким він потрібен, і вручну перевірте сумнівні результати.
4. Створити / додати. Створіть новий плейлист або виберіть існуючий, пройдіть перевірку дублікатів і явно підтвердьте запис.

> **Порада для першого запуску**  
> Почніть з невеликого трекліста на 3–10 позицій. Так простіше побачити весь цикл: імпорт → пошук → перевірка → перевірка дублікатів → запис → історія.

> **Не поспішайте з кроком 4**  
> Якщо на екрані перевірки є статус «Потрібна перевірка», краще відкрити трек і перевірити версію: оригінал / ремікс / редагована / радіоверсія / концертна версія можуть бути різними записами.

# 3. Головний екран
<a id="sec03"></a>
Головний екран — центральна панель стану. Звідси доступні 4 основні кроки, Історія, Черга, Квота, Меню, картка акаунта, поточний плейлист і швидкі файлові дії.

*Реальний головний екран v1.4.55: 4 кроки, Історія/Черга/Квота/Меню, акаунт і поточний плейлист.*

## Верхня частина головного екрана
<a id="sec03a"></a>
| Елемент | Призначення |
| --- | --- |
| ⚠ N біля версії | Компактний індикатор Центру відновлення. З’являється лише коли є стан, що потребує дії. Після відкриття поточний лічильник перестає “дихати”, доки лічильник не зміниться. |
| 1. Імпорт | Відкриває всі способи отримання локального робочого списку. |
| 2. Google / YTM | Підключення або зміна Google-акаунта, показ профілю/каналу. |
| 3. Знайти / перевірити | План пошуку, запуск пошуку і перехід до перевірки. |
| 4. Створити / додати | Вибір нового або існуючого цільового плейлиста. |
| Історія | Логічна історія плейлистів і операцій. |
| Черга | Незавершені операції пошуку або запису. |
| Квота | Локальна оцінка пошукової й загальної API-квоти. |
| Меню | Додаткові інструменти: тема, Синхронізація всіх, Центр відновлення, Дані, Сервіс тощо. |

## Картка поточного плейлиста
<a id="sec03b"></a>
Показує назву, кількість треків і стислий стан: скільки готові, скільки треба перевірити, дублікати, черга та проблеми. Натискання відкриває центр керування поточним локальним плейлистом.

> **Автовідновлення**  
> Останній робочий список зберігається локально. Це зручно після перезапускуу, але для кількох паралельних списків слід користуватися файлами Проєкту YTM.

# 4. Акаунт Google / YouTube Music
<a id="sec04"></a>
Крок 2 використовує авторизацію Google через OAuth і API даних YouTube. Після підключення застосунок отримує доступ, потрібний для читання акаунта/каналу, пошуку та явно запущених операцій із плейлистами.

## Що показує вікно акаунта
<a id="sec04a"></a>
- Статус Google-підключення.
- Маскований/відображуваний профіль Google.
- Назву каналу YouTube/YTM та його ID.
- Нагадування, що токен OAuth у цьому вікні не показується й на диск не зберігається.

## Автоматичне відновлення сесії
<a id="sec04b"></a>
При старті YTM Importer може спробувати тихо відновити Google/YTM сесію без нового ручного входу. Якщо Google відхиляє авторизацію або повертається HTTP 401, застосунок скидає статус підключення, але локальний робочий список не видаляє.

> **Якщо бачите “потрібне повторне підключення”**  
> Поверніться на головний екран → «2. Google / YTM» → увійдіть знову. Незавершені операції запису або пошуку, якщо вони вже були збережені, шукайте в Черзі або Центрі відновлення.

## Зміна акаунта
<a id="sec04c"></a>
У вікні «Акаунт» є дія «Змінити». Якщо завдання в черзі було створене для іншого каналу/акаунта, YTM Importer не повинен мовчки продовжувати його під іншим профілем — користувачу пропонується змінити акаунт або скасувати.

# 5. Імпорт: усі способи
<a id="sec05"></a>
*Усі основні джерела сходяться в один локальний «Поточний плейлист».*

## CSV, TXT або Проєкт YTM
<a id="sec05a"></a>
«1. Імпорт» → «Імпорт із файлу» → «Вибрати файл». Системний вибір файла приймає широкий тип MIME, тому що деякі постачальники файлів Android неправильно позначають CSV. Після вибору YTM Importer читає файл локально.

| Формат | Що отримуємо |
| --- | --- |
| CSV / TXT | Рядки трекліста. Далі треки зазвичай потребують пошуку та перевірки. |
| Проєкт YTM | Повноцінний робочий проєкт. Збережений точний ідентифікатор `videoId` не потребує нового запиту `search.list`. |

## Вставити текст
<a id="sec05b"></a>
Можна вставити список прямо в поле. Один трек — один рядок у форматі «Виконавець - Назва треку». Підтримуються різні тире ( -, – , — ) і нумерація на кшталт «1.» або «2)». Назва плейлиста необов’язкова.

## Імпорт із акаунта YouTube/YTM у режимі лише читання
<a id="sec05c"></a>
«Плейлист з підключеного акаунта» завантажує список плейлистів, після вибору читає його треки й створює локальний робочий список уже з точними ідентифікаторами `videoId`. Віддалений плейлист при цьому не змінюється.

> **ЛИШЕ ЧИТАННЯ**  
> Імпорт плейлиста з акаунта — лише читання. Він не додає, не видаляє й не переставляє треки у YouTube/YTM.

## Поточний робочий список
<a id="sec05d"></a>
На екрані імпорту видно автозбережений поточний список. Його можна очистити окремою явною дією. Очищення видаляє тільки локальний автозбережений робочий простір; файли Проєкту YTM й віддалені YTM плейлисти не змінюються.

## Експорт плейлистів акаунта
<a id="sec05e"></a>
Екран імпорту також містить інструменти для експорту лише для читання вибраних або всіх плейлистів акаунта. Вихід — папка з файлами Проєкту YTM та системним файлом `manifest.json`. Детально це описано в розділі 15.

# 6. Знімок за URL
<a id="sec06"></a>
«Імпорт за URL / Mix» відкриває окремий екран знімка. Ви вставляєте URL плейлиста YouTube або YouTube Music, а читання починається тільки після «Прочитати URL».

## Що показує попередній перегляд
<a id="sec06a"></a>
- Назву плейлиста, якщо її вдалося отримати.
- Загальну кількість елементів.
- Кількість унікальних точних ідентифікаторів `videoId`.
- Повторні входження однакових `videoId`.
- Недоступні / приватні / видалені елементи.
- Діагностику джерела й обробник джерела та кеш.

Попередній перегляд не змінює поточний робочий список. Пошук, перевірка і запис також не запускаються автоматично.

## Повтори: усі чи унікальні
<a id="sec06b"></a>
Якщо знайдено повторні входження одного й того самого `videoId`, застосунок може запропонувати зберегти всі елементи або тільки унікальні. Це вибір локального знімка, а не віддалене редагування плейлиста.

## Локальний кеш знімків за URL
<a id="sec06c"></a>
Результат може читатися з локального кешу. За потреби є явна дія «Оновити з YouTube». Для частини сценаріїв є окрема дія отримати назву плейлиста з API.

> **Mix**  
> Якщо обробник джерела не підтримує конкретний Mix, застосунок прямо повідомить, що цей Mix не підтримується поточним обробником. Це не означає, що ваш локальний список пошкоджено.
