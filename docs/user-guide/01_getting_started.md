# 1. Що таке YTM Імпортer
<a id="sec01"></a>
YTM Імпортer — Android-застосунок, який перетворює трекліст на керований робочий проєкт, допомагає знайти точні YouTube `videoId`, дозволяє вручну перевірити сумнівні результати, а потім створити новий плейлист або додати треки до вже існуючого YouTube / YouTube Music плейлиста.

## Основні можливості
<a id="sec01a"></a>
- Імпорт CSV, TXT, вставленого тексту та Проєкт YTM.
- У режимі лише читання імпорт плейлиста з підключеного YouTube/YTM акаунта з точними `videoId`.
- Імпорт / знімок плейлиста за URL із локальним попередній перегляд перед збереженням.
- Планування пошуку, кеш пошуку і локальна оцінка квоти.
- Перевірка кожного треку, вибір кандидата, ручне YouTube/YTM посилання, пропуск проблемного треку.
- Створення нового YTM плейлиста або додавання до існуючого з перевірка дублікатів за точний `videoId`.
- Черга / Продовження після квота/обмеження частоти запитів/авторизації пауз.
- Історія з пошуком, фільтрами, групуванням і відновленням запису як поточного робочого списку.
- Центр відновлення — єдиний екран незавершених/перерваних станів.
- Синхронізація всіх — лише для читання попередній перегляд усіх локальних плейлистів, явна сесія синхронізації, контрольна точка і точний відкат.
- Локальний повна резервна копія, Історія-only restore, safety знімок і відкат локального Restore.
- Експорт всієї/вибраної бібліотеки акаунта у Проєкт YTM + manifest, інкрементна резервна копія і зведення дельта-ланцюжка.
- Діагностика, кеш пошуку очищення, квота screen, теми, історія змін та вбудований модуль оновлення.

## Чого застосунок принципово не робить сам
<a id="sec01b"></a>
- Не запускає пошук або запис через поворот екрана, «Назад» або просте відкриття recovery-екрана.
- Не видаляє старий YouTube/YTM плейлист лише через збіг назви.
- Не вважає локальну оцінку квота точним балансом Google Cloud.
- Не зберігає OAuth токен доступу у Проєкт YTM, Діагностика або повна резервна копія.
- Не має власного сервера, реклами чи вбудованої аналітики.

# 2. Швидкий старт: 4 кроки
<a id="sec02"></a>
*Основний користувацький шлях від трекліста до готового плейлиста.*

1. Імпорт. Отримайте локальний робочий список із CSV/TXT/Проєкт YTM, вставленого тексту, плейлиста акаунта або знімок за URL.
2. Google / YTM. Підключіть Google-акаунт і переконайтесь, що YouTube/YTM канал визначено.
3. Знайти / перевірити. Запустіть пошук лише для треків, яким він потрібен, і вручну перевірте сумнівні результати.
4. Створити / додати. Створіть новий плейлист або виберіть існуючий, пройдіть перевірка дублікатів і явно підтвердьте запис.

> **Порада для першого запуску**  
> Почніть з невеликого трекліста на 3–10 позицій. Так простіше побачити весь цикл: імпорт → пошук → Перевірка → перевірка дублікатів → запис → Історія.

> **Не поспішайте з кроком 4**  
> Якщо у Перевірка є статус «Потрібна перевірка», краще відкрити трек і перевірити версію: Original / Remix / Edit / Radio / Live можуть бути різними записами.

# 3. Головний екран Головний екран
<a id="sec03"></a>
Головний екран — центральна панель стану. Звідси доступні 4 основні кроки, Історія, Черга, Quota, Меню, картка акаунта, поточний плейлист і швидкі файлові дії.

*Реальний Головний екран v1.4.55: 4 кроки, Історія/Черга/Quota/Меню, акаунт і поточний плейлист.*

## Верхня частина Головний екран
<a id="sec03a"></a>
| Елемент | Призначення |
| --- | --- |
| ⚠ N біля версії | Компактний індикатор Центр відновлення. З’являється лише коли є actionable стан. Після відкриття поточного count перестає “дихати”, доки count не зміниться. |
| 1. Імпорт | Відкриває всі способи отримання локального робочого списку. |
| 2. Google / YTM | Підключення або зміна Google-акаунта, показ профілю/каналу. |
| 3. Знайти / перевірити | План Пошук, запуск пошуку і перехід у Перевірка. |
| 4. Створити / додати | Вибір нового або існуючого цільового плейлиста. |
| Історія | Логічна історія плейлистів і операцій. |
| Черга | Незавершені Пошук/запис операції. |
| Квота | Локальна оцінка пошукової й загальної API-квоти. |
| Меню | Додаткові інструменти: тема, Синхронізація всіх, Центр відновлення, Дані, Сервіс тощо. |

## Картка поточного плейлиста
<a id="sec03b"></a>
Показує назву, кількість треків і стислий стан: скільки готові, скільки треба перевірити, дублікати, черга та проблеми. Натискання відкриває центр поточного плейлиста — керування поточним локальним плейлистом.

> **Автовідновлення**  
> Останній робочий список зберігається локально. Це зручно після перезапуску, але для кількох паралельних списків слід користуватися файлами Проєкту YTM.

# 4. Google / YouTube Music акаунт
<a id="sec04"></a>
Крок 2 використовує Google OAuth і YouTube Дані API. Після підключення застосунок отримує доступ, потрібний для читання акаунта/каналу, пошуку та явно запущених операцій із плейлистами.

## Що показує вікно акаунта
<a id="sec04a"></a>
- Статус Google-підключення.
- Маскований/відображуваний профіль Google.
- Назву YouTube/YTM каналу та ID каналу.
- Нагадування, що токен OAuth у цьому вікні не показується й на диск не зберігається.

## Автоматичне відновлення сесії
<a id="sec04b"></a>
При старті YTM Імпортer може спробувати тихо відновити Google/YTM сесію без нового ручного входу. Якщо Google відхиляє авторизацію або повертається HTTP 401, застосунок скидає статус підключення, але локальний робочий список не видаляє.

> **Якщо бачите “потрібне повторне підключення”**  
> Поверніться на Головний екран → «2. Google / YTM» → увійдіть знову. Незавершені запис/Пошук операції, якщо вони вже були збережені, шукайте в Черга або Центр відновлення.

## Зміна акаунта
<a id="sec04c"></a>
У вікні «Акаунт» є дія «Змінити». Якщо завдання в Черзі був створений для іншого каналу/акаунта, YTM Імпортer не повинен мовчки продовжувати його під іншим профілем — користувачу пропонується змінити акаунт або скасувати.

# 5. Імпорт: усі способи
<a id="sec05"></a>
*Усі основні джерела сходяться в один локальний «Поточний плейлист».*

## CSV, TXT або Проєкт YTM
<a id="sec05a"></a>
«1. Імпорт» → «Імпорт із файлу» → «Вибрати файл». Системний вибір файла приймає широкий MIME type, тому що деякі Android providers неправильно маркують CSV. Після вибору YTM Імпортer читає файл локально.

| Формат | Що отримуємо |
| --- | --- |
| CSV / TXT | Рядки трекліста. Далі треки зазвичай потребують Пошук/Перевірка. |
| Проєкт YTM | Повноцінний робочий проєкт. Exact `videoId`, якщо були збережені, не потребують нового search.list. |

## Вставити текст
<a id="sec05b"></a>
Можна вставити список прямо в поле. Один трек — один рядок у форматі «Artist - Track». Підтримуються різні тире ( -, – , — ) і нумерація на кшталт «1.» або «2)». Назва плейлиста необов’язкова.

## У режимі лише читання імпорт із акаунта YouTube/YTM
<a id="sec05c"></a>
«Плейлист з підключеного акаунта» завантажує список плейлистів, після вибору читає його треки й створює локальний робочий список уже з точними `videoId`. Віддалений плейлист при цьому не змінюється.

> **ЛИШЕ ЧИТАННЯ**  
> Імпорт плейлиста з акаунта — лише читання. Він не додає, не видаляє й не переставляє треки у YouTube/YTM.

## Поточний робочий список
<a id="sec05d"></a>
На екрані Імпорт видно автозбережений поточний список. Його можна очистити окремою явною дією. Очищення видаляє тільки локальний автозбережений робочий простір; файли Проєкту YTM й віддалені YTM плейлисти не змінюються.

## Експорт плейлистів акаунта
<a id="sec05e"></a>
Імпорт також містить інструменти для лише для читання експорту вибраних або всіх плейлистів акаунта. Вихід — папка з файлами Проєкту YTM та `manifest.json`. Детально це описано в розділі 15.

# 6. Знімок за URL
<a id="sec06"></a>
«Імпорт за URL / Mix» відкриває окремий екран знімка. Ви вставляєте URL плейлиста YouTube або YouTube Music, а читання починається тільки після «Прочитати URL».

## Що показує попередній перегляд
<a id="sec06a"></a>
- Назву плейлиста, якщо її вдалося отримати.
- Загальну кількість елементів.
- Кількість унікальних точний `videoId`.
- Повторні входження точний `videoId`.
- Недоступні / private / deleted елементи.
- Діагностику джерела й resolver/cache.

Попередній перегляд не змінює поточний робочий список. Пошук, Перевірка і запис також не запускаються автоматично.

## Повтори: усі чи унікальні
<a id="sec06b"></a>
Якщо знайдено повторні входження точний `videoId`, застосунок може запропонувати зберегти всі елементи або тільки унікальні. Це вибір локального знімок, а не віддаленої редагування плейлиста.

## Локальний кеш знімок за URL
<a id="sec06c"></a>
Результат може читатися з локального cache. За потреби є явна дія «Оновити з YouTube». Для частини сценаріїв є окрема дія отримати назву плейлиста з API.

> **Mix**  
> Якщо resolver не підтримує конкретний Mix, застосунок прямо повідомить «Mix не підтримується цим resolver». Це не означає, що ваш локальний список пошкоджено.
