# 14. Дані та локальні резервні копії
<a id="sec14"></a>
*Локальний Full Backup та backup бібліотеки акаунта — різні формати з різними задачами.*

## Повна резервна копія
<a id="sec14a"></a>
Меню → «Дані» → «Повна резервна копія». Файл YTM_Backup_*.json зберігає History, Queue, поточний робочий список, SearchCache та URL snapshot cache. Quota counters додаються для діагностики, але при Restore не застосовуються. Файл має SHA-256 integrity check.

## Restore Full Backup
<a id="sec14b"></a>
Restore замінює локальні History, Queue, робочий список і caches, але не змінює remote YouTube/YTM плейлисти та не відкочує локальну оцінку quota. Перед Restore автоматично створюється safety snapshot поточного стану.

## History-only Restore
<a id="sec14c"></a>
«Відновити лише історію» приймає YTM_History_*.json і замінює тільки History. Queue, quota, SearchCache і поточний робочий список не змінюються. Перед імпортом також створюється safety snapshot повного локального стану.

## Rollback останнього Restore
<a id="sec14d"></a>
Якщо Restore або History import дали небажаний результат, можна повернути локальний стан зі safety snapshot. Quota залишається поточною, а remote YouTube/YTM не змінюється. Snapshot можна окремо видалити, після чого цей rollback стане неможливим.

## Експорт і Share
<a id="sec14e"></a>
| Дія | Формат |
| --- | --- |
| Історія TXT | Людинозрозумілий звіт. |
| Історія JSON | Технічний restorable експорт History. |
| Черга → JSON | Технічний експорт Pending Queue. |
| Поділитися History TXT | Android Share. |
| Поділитися повним backup | Android Share після попередження про чутливі дані. |

# 15. Backup бібліотеки YouTube/YTM акаунта
<a id="sec15"></a>
Це інша система, ніж «Повна локальна копія» в Data. Тут зберігається структура remote бібліотеки акаунта як папка з YTM Project файлами та manifest.json.

## Вибірковий та повний export
<a id="sec15a"></a>
- «Вибрати плейлисти для експорту» — вибрати один або кілька плейлистів.
- «Експортувати всі плейлисти в папку» — зберегти всю доступну бібліотеку акаунта.
- Експорт read-only: YouTube/YTM не змінюється.
- У папці створюються YTM Project файли та manifest.json з індексом.

## Відкрити backup / manifest.json
<a id="sec15b"></a>
YTM Importer читає manifest локально, показує знайдені YTM Project файли й дозволяє відкрити один плейлист як локальний робочий список без YouTube API.

## Incremental backup
<a id="sec15c"></a>
«Оновити backup (incremental)» використовує попередню backup-сесію як baseline, читає поточні плейлисти й класифікує NEW / UPDATED / UNCHANGED / MISSING. Старий backup не змінюється й не видаляється; створюється нова delta-папка.

Preflight окремо показує режим ALL/SELECTED, кількість плейлистів і оцінку playlistItems.list. Search і write API для цього workflow дорівнюють нулю; застосунок лише читає remote вміст.

## Зібрати повний backup з ланцюжка
<a id="sec15d"></a>
Застосунок сканує локальні backup-сесії, знаходить кінцеві delta heads, відновлює логічний стан ланцюжка і створює новий самодостатній повний backup. Ця операція локальна: YouTube API = 0, вихідні папки не змінюються.

> **Delta ≠ Full**  
> Якщо ви відкрили manifest інкрементальної delta, застосунок прямо попередить, що це не повний export. Для самодостатнього стану використайте «Зібрати повний backup з ланцюжка».

# 16. Файли, папки та Android-дозволи
<a id="sec16"></a>
## Recent File Chooser
<a id="sec16a"></a>
YTM Importer має власний екран «Останні файли» перед системним Android picker. Він може показувати файли з Download і з папок, які ви раніше надали через SAF.

> **ПОТОЧНА ГІЛКА #54**  
> Для Full Restore і History Import актуальна гілка вміє перевіряти вміст JSON у фоні та показувати в основному списку тільки файли потрібного типу. Тип визначається за структурою/format усередині файла, а не за назвою або .json. «Інший файл…» зберігає fallback для legacy/зовнішніх файлів.

| Кнопка | Для чого |
| --- | --- |
| Надати доступ до всіх файлів | На Android 11+ дозволяє напряму читати Download і автоматично сортувати знайдені файли за last modified. |
| Додати папку… | Додати окремий SAF root через системний вибір папки. |
| Інший файл… / Системний вибір… | Відкрити стандартний Android file picker як fallback. |
| Скасувати | Повернутися без вибору файла. |

## Storage Chooser
<a id="sec16b"></a>
Для збереження/експорту використовується окремий список пам’ятних SAF-папок. Android може зберігати доступ, тому ту саму папку можна використовувати повторно без нового проходу через системний провідник.

- «Додати папку…» — надати новий SAF root.
- «Зберегти як…» — стандартне ACTION_CREATE_DOCUMENT.
- Для деяких дій достатньо read permission, для запису потрібні read+write.

> **Про корінь Download**  
> Android 11+ не дозволяє додати корінь Download через ACTION_OPEN_DOCUMENT_TREE. Для автоматичного читання Download використовується окремий «Доступ до всіх файлів» або системний picker як fallback.

# 17. Квота YouTube API і SearchCache
<a id="sec17"></a>
Екран «Квота» показує локальну оцінку: search calls, залишок пошуків, інші API units, залишок інших units, cache hits, кількість pending jobs і день квоти.

> **Це не точний баланс Google Cloud**  
> Локальна оцінка враховує тільки операції, які зафіксував цей YTM Importer на цьому телефоні. Інші пристрої або клієнти того самого API project теж можуть витрачати quota. Точний стан дивіться в Google Cloud Console.

## Дві різні “квоти”
<a id="sec17a"></a>
Search має окремий денний ліміт у логіці застосунку, а 10 000 units стосуються інших YouTube Data API операцій. Крім цього YouTube може тимчасово обмежити частоту write-запитів — це rate limit, а не обов’язково вичерпання добової quota.

## SearchCache
<a id="sec17b"></a>
SearchCache зберігає результати пошуку, щоб повторно не витрачати search.list для того самого треку. У Service можна переглянути статистику, видалити тільки прострочені записи або очистити весь cache.

> **Що не видаляється при очищенні cache**  
> History, Pending Queue та YouTube/YTM плейлисти не змінюються. Але наступний пошук очищених треків знову витрачатиме quota.

# 18. Сервіс, Diagnostics і оновлення
<a id="sec18"></a>
## Швидкий старт і приватність
<a id="sec18a"></a>
Service містить вбудовану коротку довідку 4 кроків та окремий privacy-екран із поясненням Google OAuth, локальних даних, backup і незалежного статусу застосунку.

## Diagnostics
<a id="sec18b"></a>
Diagnostics збирає стан акаунта, поточного імпорту, локальної quota estimate, SearchCache, History і Pending Queue. Звіт можна зберегти або поділитися як TXT.

> **Diagnostics маскує і не включає секрети**  
> Звіт не містить OAuth access token, Google password або signing keys. Email та Channel ID передаються замаскованими.

## Про застосунок і changelog
<a id="sec18c"></a>
Екран «Про YTM Importer» показує версію, можливості та принципи. «Історія змін» читає CHANGELOG.md, вбудований у APK під час build, і показує найновіші релізи першими.

## Вбудований updater
<a id="sec18d"></a>
1. Натиснути «Перевірити оновлення».
2. Якщо є нова стабільна версія — явно натиснути «Завантажити APK».
3. YTM Importer перевіряє SHA-256 завантаженого APK.
4. Після успішної перевірки стає доступна «Встановити».
5. Якщо Android не дозволяє інсталяцію з цього джерела, відкрийте системний дозвіл, поверніться й натисніть «Встановити» ще раз.

> **Джерело оновлень**  
> Updater перевіряє офіційний GitHub Release репозиторію faric-ua/YTM. APK не завантажується без явного натискання.

# 19. Теми оформлення

# 20. Приватність і безпека даних
<a id="sec20"></a>
| Дані | Де можуть зберігатися / використовуватися |
| --- | --- |
| OAuth access token | Використовується для API-сесії, але не входить у YTM Project, Diagnostics або Full Backup. |
| Google email / Channel ID | Можуть входити у Full Backup та локальний стан; Diagnostics їх маскує. |
| History / Queue / SearchCache / current workspace | Локально на телефоні; частина Full Backup. |
| YTM Project | Містить робочий плейлист, треки та exact videoId/зв’язки, але не OAuth token. |
| Android Share | YTM Importer сам не завантажує файл на власний сервер; після вибору іншого застосунку передача залежить від нього. |

## Що може бути чутливим у Full Backup
<a id="sec20a"></a>
Повна локальна копія може містити email, Channel ID, назви плейлистів, History, Queue, поточний робочий список, SearchCache і URL snapshot cache. Надсилайте такий файл тільки туди, де довіряєте одержувачу.

> **Незалежний інструмент**  
> YTM Importer не є офіційним застосунком Google або YouTube і не має власного сервера, реклами чи вбудованої аналітики.
