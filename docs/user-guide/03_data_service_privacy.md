# 14. Дані та локальні резервні копії
<a id="sec14"></a>
*Локальний повна резервна копія та резервна копія бібліотеки акаунта — різні формати з різними задачами.*

## Повна резервна копія
<a id="sec14a"></a>
Меню → «Дані» → «Повна резервна копія». Файл YTM_«Назад»up_*.json зберігає Історія, Черга, поточний робочий список, кеш пошуку та знімок за URL cache. Quota counters додаються для діагностики, але при Restore не застосовуються. Файл має SHA-256 integrity check.

## Restore повна резервна копія
<a id="sec14b"></a>
Restore замінює локальні Історія, Черга, робочий список і caches, але не змінює remote YouTube/YTM плейлисти та не відкочує локальну оцінку квота. Перед Restore автоматично створюється safety знімок поточного стану.

## Історія-only Restore
<a id="sec14c"></a>
«Відновити лише історію» приймає YTM_Історія_*.json і замінює тільки Історія. Черга, квота, кеш пошуку і поточний робочий список не змінюються. Перед імпортом також створюється safety знімок повного локального стану.

## Rollback останнього Restore
<a id="sec14d"></a>
Якщо Restore або імпорту Історії дали небажаний результат, можна повернути локальний стан зі safety знімок. Quota залишається поточною, а remote YouTube/YTM не змінюється. Snapshot можна окремо видалити, після чого цей відкат стане неможливим.

## Експорт і Поділитися
<a id="sec14e"></a>
| Дія | Формат |
| --- | --- |
| Історія TXT | Людинозрозумілий звіт. |
| Історія JSON | Технічний restorable експорт Історія. |
| Черга → JSON | Технічний експорт Pending Черга. |
| Поділитися Історія TXT | системне меню «Поділитися» Android. |
| Поділитися повним резервна копія | системне меню «Поділитися» Android після попередження про чутливі дані. |

# 15. «Назад»up бібліотеки YouTube/YTM акаунта
<a id="sec15"></a>
Це інша система, ніж «Повна локальна копія» в Дані. Тут зберігається структура remote бібліотеки акаунта як папка з файлами Проєкту YTM та `manifest.json`.

## Вибірковий та повний export
<a id="sec15a"></a>
- «Вибрати плейлисти для експорту» — вибрати один або кілька плейлистів.
- «Експортувати всі плейлисти в папку» — зберегти всю доступну бібліотеку акаунта.
- Експорт лише для читання: YouTube/YTM не змінюється.
- У папці створюються файли Проєкту YTM та `manifest.json` з індексом.

## Відкрити резервна копія / `manifest.json`
<a id="sec15b"></a>
YTM Імпортer читає manifest локально, показує знайдені файли Проєкту YTM й дозволяє відкрити один плейлист як локальний робочий список без YouTube API.

## Incremental резервна копія
<a id="sec15c"></a>
«Оновити резервну копію (інкрементно)» використовує попередню резервна копія-сесію як baseline, читає поточні плейлисти й класифікує NEW / UPDATED / UNCHANGED / MISSING. Старий резервна копія не змінюється й не видаляється; створюється нова дельта-папка.

Preflight окремо показує режим ALL/SELECTED, кількість плейлистів і оцінку playlistItems.list. Пошук і запис API для цього сценарій дорівнюють нулю; застосунок лише читає remote вміст.

## Зібрати повний резервна копія з ланцюжка
<a id="sec15d"></a>
Застосунок сканує локальні резервна копія-сесії, знаходить кінцеві дельта heads, відновлює логічний стан ланцюжка і створює новий самодостатній повний резервна копія. Ця операція локальна: YouTube API = 0, вихідні папки не змінюються.

> **Дельта ≠ Full**  
> Якщо ви відкрили manifest інкрементальної дельта, застосунок прямо попередить, що це не повний export. Для самодостатнього стану використайте «Зібрати повний резервна копія з ланцюжка».

# 16. Файли, папки та Android-дозволи
<a id="sec16"></a>
## Recent File Chooser
<a id="sec16a"></a>
YTM Імпортer має власний екран «Останні файли» перед системним Android вибір файла. Він може показувати файли з Download і з папок, які ви раніше надали через SAF.

> **ПОТОЧНА ГІЛКА #54**  
> Для повне відновлення і Історія Імпорт актуальна гілка вміє перевіряти вміст JSON у фоні та показувати в основному списку тільки файли потрібного типу. Тип визначається за структурою/format усередині файла, а не за назвою або .json. «Інший файл…» зберігає fallback для legacy/зовнішніх файлів.

| Кнопка | Для чого |
| --- | --- |
| Надати доступ до всіх файлів | На Android 11+ дозволяє напряму читати Download і автоматично сортувати знайдені файли за last modified. |
| Додати папку… | Додати окремий SAF root через системний вибір папки. |
| Інший файл… / Системний вибір… | Відкрити стандартний Android file вибір файла як fallback. |
| Скасувати | Повернутися без вибору файла. |

## екран вибору папки
<a id="sec16b"></a>
Для збереження/експорту використовується окремий список пам’ятних SAF-папок. Android може зберігати доступ, тому ту саму папку можна використовувати повторно без нового проходу через системний провідник.

- «Додати папку…» — надати новий SAF root.
- «Зберегти як…» — стандартне ACTION_CREATE_DOCUMENT.
- Для деяких дій достатньо read permission, для запису потрібні read+запис.

> **Про корінь Download**  
> Android 11+ не дозволяє додати корінь Download через ACTION_OPEN_DOCUMENT_TREE. Для автоматичного читання Download використовується окремий «Доступ до всіх файлів» або системний вибір файла як fallback.

# 17. Квота YouTube API і кеш пошуку
<a id="sec17"></a>
Екран «Квота» показує локальну оцінку: search calls, залишок пошуків, інші API units, залишок інших units, cache hits, кількість pending jobs і день квоти.

> **Це не точний баланс Google Cloud**  
> Локальна оцінка враховує тільки операції, які зафіксував цей YTM Імпортer на цьому телефоні. Інші пристрої або клієнти того самого API project теж можуть витрачати квота. Точний стан дивіться в Google Cloud Console.

## Дві різні “квоти”
<a id="sec17a"></a>
Пошук має окремий денний ліміт у логіці застосунку, а 10 000 units стосуються інших YouTube Дані API операцій. Крім цього YouTube може тимчасово обмежити частоту запис-запитів — це rate limit, а не обов’язково вичерпання добової квота.

## кеш пошуку
<a id="sec17b"></a>
кеш пошуку зберігає результати пошуку, щоб повторно не витрачати search.list для того самого треку. У Сервіс можна переглянути статистику, видалити тільки прострочені записи або очистити весь cache.

> **Що не видаляється при очищенні cache**  
> Історія, Pending Черга та YouTube/YTM плейлисти не змінюються. Але наступний пошук очищених треків знову витрачатиме квота.

# 18. Сервіс, Діагностика і оновлення
<a id="sec18"></a>
## Швидкий старт і приватність
<a id="sec18a"></a>
Сервіс містить вбудовану коротку довідку 4 кроків та окремий privacy-екран із поясненням Google OAuth, локальних даних, резервна копія і незалежного статусу застосунку.

## Діагностика
<a id="sec18b"></a>
Діагностика збирає стан акаунта, поточного імпорту, локальної квота estimate, кеш пошуку, Історія і Pending Черга. Звіт можна зберегти або поділитися як TXT.

> **Діагностика маскує і не включає секрети**  
> Звіт не містить OAuth токен доступу, Google password або signing keys. Email та ID каналу передаються замаскованими.

## Про застосунок і історія змін
<a id="sec18c"></a>
Екран «Про YTM Імпортer» показує версію, можливості та принципи. «Історія змін» читає CHANGELOG.md, вбудований у APK під час build, і показує найновіші релізи першими.

## Вбудований модуль оновлення
<a id="sec18d"></a>
1. Натиснути «Перевірити оновлення».
2. Якщо є нова стабільна версія — явно натиснути «Завантажити APK».
3. YTM Імпортer перевіряє SHA-256 завантаженого APK.
4. Після успішної перевірки стає доступна «Встановити».
5. Якщо Android не дозволяє інсталяцію з цього джерела, відкрийте системний дозвіл, поверніться й натисніть «Встановити» ще раз.

> **Джерело оновлень**  
> Updater перевіряє офіційний GitHub Release репозиторію faric-ua/YTM. APK не завантажується без явного натискання.

# 19. Теми оформлення
<a id="sec19"></a>
*Реальний екран Меню. Тут знаходиться Theme, Синхронізація всіх, Центр відновлення, Дані і Сервіс.*

Меню → «Тема». Доступні три вбудовані Skin: Neon Dark, Blue Dark і Green Dark. Вибір спочатку показується як попередній перегляд; активна тема зміниться тільки після «Застосувати».

- Neon Dark — основний контрастний neon-акцент.
- Blue Dark — синя спокійніша палітра.
- Green Dark — зелена альтернативна палітра.

Попередній перегляд показує службові кольори: поверхня/акцент, успіх, попередження, небезпека, дублікат. Тема зберігається на пристрої.

# 20. Приватність і безпека даних
<a id="sec20"></a>
| Дані | Де можуть зберігатися / використовуватися |
| --- | --- |
| OAuth токен доступу | Використовується для API-сесії, але не входить у Проєкт YTM, Діагностика або повна резервна копія. |
| електронна адреса Google / ID каналу | Можуть входити у повна резервна копія та локальний стан; Діагностика їх маскує. |
| Історія / Черга / кеш пошуку / поточний робочий простір | Локально на телефоні; частина повна резервна копія. |
| Проєкт YTM | Містить робочий плейлист, треки та точний `videoId`/зв’язки, але не токен OAuth. |
| системне меню «Поділитися» Android | YTM Імпортer сам не завантажує файл на власний сервер; після вибору іншого застосунку передача залежить від нього. |

## Що може бути чутливим у повна резервна копія
<a id="sec20a"></a>
Повна локальна копія може містити email, ID каналу, назви плейлистів, Історія, Черга, поточний робочий список, кеш пошуку і знімок за URL cache. Надсилайте такий файл тільки туди, де довіряєте одержувачу.

> **Незалежний інструмент**  
> YTM Імпортer не є офіційним застосунком Google або YouTube і не має власного сервера, реклами чи вбудованої аналітики.
