## Правило безпеки, яке має залишатися видимим у документації

Поворот екрана, Back, повторне відкриття Activity, History, Queue, Recovery Center або preview-екрана **не повинні самі запускати** Search, remote write, Restore, Rollback, Delete чи іншу мутацію. Якщо функціональний контракт зміниться, інструкцію треба оновити разом із source/QA evidence.

## Як підтримувати цю документацію

1. Нову користувацьку функцію додавати в тематичний розділ, а не лише в changelog.
2. Новий повноцінний екран — додати до цього індексу та, якщо треба, до практичних сценаріїв.
3. Зміну небезпечного workflow (Restore/Delete/Write/Rollback) описувати разом із наслідками та підтвердженнями.
4. Новий формат файла — оновити розділ 16 і Appendix A.
5. Після великої зміни оновити дату та source snapshot.
6. PHONE PASS не змішувати зі static/build evidence: якщо функція тільки є в source, прямо позначати її як поточну гілку.
7. DOCX після значних змін треба перегенерувати та візуально перевірити всі сторінки.
