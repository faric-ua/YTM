## Правило безпеки, яке має залишатися видимим у документації

Поворот екрана, «Назад», повторне відкриття Activity, Історія, Черга, Центр відновлення або попередній перегляд-екрана **не повинні самі запускати** Пошук, віддалений запис, Restore, Rollback, Delete чи іншу мутацію. Якщо функціональний контракт зміниться, інструкцію треба оновити разом із вихідний код/QA evidence.

## Як підтримувати цю документацію

1. Нову користувацьку функцію додавати в тематичний розділ, а не лише в історія змін.
2. Новий повноцінний екран — додати до цього індексу та, якщо треба, до практичних сценаріїв.
3. Зміну небезпечного сценарій (Restore/Delete/Write/Rollback) описувати разом із наслідками та підтвердженнями.
4. Новий формат файла — оновити розділ 16 і Додаток A.
5. Після великої зміни оновити дату та знімок вихідного коду.
6. ПЕРЕВІРЕНО НА ТЕЛЕФОНІ не змішувати зі статичні перевірки та перевірки збірки: якщо функція тільки є в вихідний код, прямо позначати її як поточну гілку.
7. DOCX після значних змін треба перегенерувати та візуально перевірити всі сторінки.
