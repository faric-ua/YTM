# 7. Пошук і Review
<a id="sec07"></a>
*Користувацькі стани треку, які можна зустріти у Review та пов’язаних екранах.*

## План пошуку перед запуском
<a id="sec07a"></a>
Перед Search YTM Importer показує план: скільки треків у списку, скільки реально потребують пошуку, скільки вже є в кеші, скільки нових search.list запитів приблизно знадобиться та яка локальна оцінка доступної квоти.

> **SearchCache економить квоту**  
> Трек із exact videoId або валідним кешованим результатом не повинен даремно витрачати новий search.list. Повторний Search планує тільки те, що справді потребує пошуку.

## Фільтри Review
<a id="sec07b"></a>
| Фільтр | Що показує |
| --- | --- |
| Усі | Весь трекліст. |
| Перев. | Треки, які потребують ручної уваги. |
| Готові | Треки, готові до запису. |
| Пробл. | Не знайдено / помилка / інші проблемні стани. |

## Ручна перевірка одного треку
<a id="sec07c"></a>
У detail видно оригінальний рядок, автоматично знайдений результат або ручний вибір, а також список кандидатів. Для кандидата доступні «Використати» і «Відкрити YTM».

- Вставити YouTube / YTM URL — вручну задати потрібне відео; застосунок намагається отримати реальну назву та канал через API.
- Пропустити цей трек — залишити позицію в локальному списку, але не записувати її.
- Повторити пошук — повторно шукати тільки там, де це потрібно; exact videoId і cache не повинні зайво витрачати quota.

## YTM Project з Review
<a id="sec07d"></a>
Review дозволяє зберегти або поділитися поточним YTM Project. Це найкращий формат, якщо треба відкласти роботу й пізніше відкрити той самий список із уже перевіреними exact videoId.

# 8. Поточний плейлист / Playlist Hub
<a id="sec08"></a>
Playlist Hub відкривається з картки поточного плейлиста на Home. Це локальний центр керування одним робочим списком.

| Дія | Що робить |
| --- | --- |
| Треки / перевірка | Відкриває Review з усіма фільтрами та ручним вибором. |
| Знайти / перевірити | Запускає план Search лише для потрібних треків. |
| Створити / додати в YTM | Переходить до вибору цільового плейлиста. |
| Проєкт YTM / експорт | Зберегти або поділитися поточним робочим проєктом. |
| Заміни / проблемні треки | Журнал ручних замін, пропусків, дублікатів, missing і помилок. |
| Відкрити в YouTube Music | Відкрити останній цільовий плейлист, якщо відомий ID. |
| Копіювати посилання | Скопіювати URL цільового YTM плейлиста. |

## Журнал замін

# 9. Створення або додавання в YTM
<a id="sec09"></a>
*Запис у YTM виконується після вибору цілі та duplicate check.*

## Створити новий плейлист
<a id="sec09a"></a>
Можна змінити назву перед створенням і вибрати приватність: Приватний, За посиланням або Публічний. Після явного підтвердження застосунок створює плейлист і додає готові треки.

## Додати в існуючий плейлист
<a id="sec09b"></a>
Плейлисти завантажуються тільки після натискання «Вибрати існуючий плейлист». Є пошук за назвою. Натискання плитки вибирає ціль; довге натискання або ⋮ відкриває дії з плейлистом.

## Редагування та видалення існуючого плейлиста
<a id="sec09c"></a>
Для доступного власного плейлиста можна змінити назву/приватність або видалити його. Видалення — віддалена необоротна дія й має окреме підтвердження.

> **УВАГА**  
> Редагування та видалення існуючого плейлиста змінюють YouTube/YTM безпосередньо. Перед підтвердженням перевірте назву та акаунт.

## Duplicate check
<a id="sec09d"></a>
Перед додаванням до існуючого плейлиста YTM Importer порівнює exact videoId, а не назви. Показується: скільки вибрано, скільки вже є в playlist, скільки повторів усередині імпорту і скільки реально нових.

| Режим | Результат |
| --- | --- |
| Пропустити дублікати й додати | Записуються тільки нові videoId; дублікати залишаються локально позначеними як пропущені. |
| Додати все одно | Явна спроба записати всі вибрані треки, включно з повторними videoId. |
| Продовжити без перевірки | Доступно лише якщо duplicate check не вдалося завершити; користувач свідомо приймає ризик повторів. |

## Результат операції
<a id="sec09e"></a>
Фінальна модалка показує «Додано / Не додано / Дублікати / Помилки», а для проблемних треків — назви та причини. За наявності playlistId можна відкрити плейлист у YTM або скопіювати посилання.

> **Rate limit / quota pause**  
> Якщо YouTube тимчасово обмежив частоту write-запитів або закінчилась квота, YTM Importer зберігає незавершену роботу в Queue. Автоматичного повтору немає.

# 10. Черга / Pending Queue
<a id="sec10"></a>
Queue містить незавершені Search або write операції, які можна явно продовжити. Вона з’являється при quota/rate-limit/auth паузах або інших відновлюваних станах.

*Приклад detail write-job у Queue: пауза через забагато write-запитів, 0/3 додано, 3 очікують.*

## Типи завдань
<a id="sec10a"></a>
| Тип | Що зберігається |
| --- | --- |
| Пошук | Snapshot плейлиста та список треків, які ще очікують Search. |
| Запис | Ціль, прогрес додавання, remainingTracks, помилки, причина паузи та прив’язка до акаунта/каналу. |

## Дії
<a id="sec10b"></a>
- Продовжити / Продовжити пошук — єдина явна команда на відновлення роботи.
- Відкрити плейлист у YTM — якщо playlistId уже відомий.
- Видалити з черги — видаляє тільки локальне завдання; вже додані remote треки не видаляються.

> **Без автоматичного Resume**  
> Перезапуск застосунку, відкриття Queue або rotation не повинні самі продовжувати Search/write.

# 11. Історія
<a id="sec11"></a>
History — довгостроковий локальний журнал операцій. У поточному UI один логічний плейлист показується однією карткою, а окремі операції залишаються доступними всередині групи.

*Приклад History detail для операції, призупиненої через API limit.*

## Пошук і фільтр
<a id="sec11a"></a>
Історія має текстовий пошук і семантичний фільтр. Вони працюють разом. У групі видно кількість операцій та дату останньої зміни.

## Що є в detail
<a id="sec11b"></a>
- Дата, джерело, тип destination і приватність.
- Результат операції та лічильники: додано, дублікати, пропущено, очікує, помилки, не знайдено.
- Заміни та проблемні треки.
- Акаунт/канал для remote-операцій.
- Остання помилка, якщо є.

## Швидкі дії History
<a id="sec11c"></a>
| Дія | Наслідок |
| --- | --- |
| Відкрити плейлист у YTM | Відкриває remote playlist, якщо відомий ID. |
| Відновити як поточний плейлист | Локально робить цей snapshot поточним. Search/write не стартують автоматично. |
| Зберегти / Поділитися YTM Project | Створює проєкт із даними конкретної History-операції. |
| Копіювати підсумок / журнал проблем | Копіює текст у буфер. |
| Видалити локальний запис | Видаляє лише History entry; YouTube/YTM плейлист не змінюється. |

> **Existing playlist import batch**  
> Якщо History стосується додавання до вже існуючого плейлиста, експортований YTM Project міститиме треки цієї операції, а не повну стару remote-бібліотеку плейлиста.

# 12. Центр відновлення
<a id="sec12"></a>
*Recovery Center не виконує recovery сам — він веде до конкретного власника стану.*

*Реальний Recovery Center v1.4.55: actionable стани зверху, завершені з попередженням окремо.*

Recovery Center збирає локально збережені незавершені або перервані стани з Queue, Bulk Session і релевантної History. Відкриття екрана нічого не продовжує автоматично.

## Секції
<a id="sec12a"></a>
| Секція | Значення |
| --- | --- |
| Потребує уваги | Є явна наступна дія: відкрити Queue, Bulk session або History. |
| Завершено з попередженням | Операція термінальна, але результат частковий/із помилкою і його корисно переглянути. |
| Нічого незавершеного | Queue/Bulk/History не містять станів, що потребують дії. |

## Індикатор ⚠ N
<a id="sec12b"></a>
Home показує компактний ⚠ N тільки коли є actionable записи. Після відкриття Recovery Center поточний count вважається acknowledged; значок перестає “дихати” і знову приверне увагу, коли count зміниться.

# 13. Синхронізувати всі / Bulk Sync
<a id="sec13"></a>
Bulk Sync призначений для масового приведення локальної бібліотеки до YouTube/YTM. Це окремий керований workflow: спочатку read-only preview, потім створення durable сесії, і лише після окремого підтвердження — remote write.

## Read-only Preview
<a id="sec13a"></a>
Меню → «Синхронізувати всі». Preview читає локальні плейлисти та remote snapshot і класифікує їх, але нічого не змінює у YouTube Music.

| Стан | Значення |
| --- | --- |
| NEW / Новий | Потрібно створити remote playlist. |
| LINKED / Пов’язано з YTM | Remote playlist уже відомий; можна доповнити. |
| ALREADY_SYNCED | Змін не потрібно. |
| NEEDS_SEARCH | Є треки без готового exact videoId. |
| PENDING | Для плейлиста вже існує незавершене завдання. |
| BLOCKED | Синхронізація зараз небезпечна/неможлива; потрібне ручне вирішення. |

У Preview користувач бачить локальні треки, готовність, заплановане створення/додавання, причину, оцінку Search і окрему оцінку write API units.

## Створення сесії
<a id="sec13b"></a>
Після підтвердження створюється локальний checkpoint і свіжий read-only remote baseline. Навіть після цього write не починається автоматично: сесія відкривається в стані готовності до явного запуску.

## Bulk Session
<a id="sec13c"></a>
*Приклад Bulk Session: частково завершено, checkpoint збережено, remote baseline відомий.*

Сесія показує стан, кількість плейлистів у плані, створені плейлисти, додані/не додані треки, actionable попередження, checkpoint, remote snapshot і деталі помилок.

- Почати синхронізацію — явний старт remote write.
- Продовжити — явне відновлення paused/interrupted сесії.
- Відкотити цю синхронізацію — exact rollback тільки тих mutation, які записані в ledger цієї сесії.
- Продовжити відкат — явне відновлення paused rollback.

## Rollback
<a id="sec13d"></a>
Rollback не шукає “схожі” плейлисти за назвою. Він використовує точний ledger сесії: додані playlistItemId/videoId і плейлисти, створені саме цією сесією. Раніше існуючі плейлисти та треки за назвою не видаляються.

> **Ключова гарантія**  
> Після перезапуску Bulk Sync або rollback не продовжуються автоматично. Користувач завжди бачить durable стан і запускає продовження сам.
