# 7. Пошук і Перевірка
<a id="sec07"></a>
*Користувацькі стани треку, які можна зустріти у Перевірка та пов’язаних екранах.*

## План пошуку перед запуском
<a id="sec07a"></a>
Перед Пошук YTM Імпортer показує план: скільки треків у списку, скільки реально потребують пошуку, скільки вже є в кеші, скільки нових search.list запитів приблизно знадобиться та яка локальна оцінка доступної квоти.

> **кеш пошуку економить квоту**  
> Трек із точний `videoId` або валідним кешованим результатом не повинен даремно витрачати новий search.list. Повторний Пошук планує тільки те, що справді потребує пошуку.

## Фільтри Перевірка
<a id="sec07b"></a>
| Фільтр | Що показує |
| --- | --- |
| Усі | Весь трекліст. |
| Перев. | Треки, які потребують ручної уваги. |
| Готові | Треки, готові до запису. |
| Пробл. | Не знайдено / помилка / інші проблемні стани. |

## Ручна перевірка одного треку
<a id="sec07c"></a>
У detail видно оригінальний рядок, автоматично знайдений результат або ручний вибір, а також список кандидатів. Для кандидата доступні «Використати» і «Відкрити YTM».

- Вставити YouTube / YTM URL — вручну задати потрібне відео; застосунок намагається отримати реальну назву та канал через API.
- Пропустити цей трек — залишити позицію в локальному списку, але не записувати її.
- Повторити пошук — повторно шукати тільки там, де це потрібно; точний `videoId` і cache не повинні зайво витрачати квота.

## Проєкт YTM з Перевірка
<a id="sec07d"></a>
Перевірка дозволяє зберегти або поділитися поточним Проєкт YTM. Це найкращий формат, якщо треба відкласти роботу й пізніше відкрити той самий список із уже перевіреними точний `videoId`.

# 8. Поточний плейлист / центр поточного плейлиста
<a id="sec08"></a>
центр поточного плейлиста відкривається з картки поточного плейлиста на Головний екран. Це локальний центр керування одним робочим списком.

| Дія | Що робить |
| --- | --- |
| Треки / перевірка | Відкриває Перевірка з усіма фільтрами та ручним вибором. |
| Знайти / перевірити | Запускає план Пошук лише для потрібних треків. |
| Створити / додати в YTM | Переходить до вибору цільового плейлиста. |
| Проєкт YTM / експорт | Зберегти або поділитися поточним робочим проєктом. |
| Заміни / проблемні треки | Журнал ручних замін, пропусків, дублікатів, missing і помилок. |
| Відкрити в YouTube Music | Відкрити останній цільовий плейлист, якщо відомий ID. |
| Копіювати посилання | Скопіювати URL цільового YTM плейлиста. |

## Журнал замін
<a id="sec08a"></a>
Є короткий формат для TikTok/публікації та повний текстовий журнал. Для кожної позиції можна бачити оригінал, результат, канал, статус або помилку.

# 9. Створення або додавання в YTM
<a id="sec09"></a>
*Запис у YTM виконується після вибору цілі та перевірка дублікатів.*

## Створити новий плейлист
<a id="sec09a"></a>
Можна змінити назву перед створенням і вибрати приватність: Приватний, За посиланням або Публічний. Після явного підтвердження застосунок створює плейлист і додає готові треки.

## Додати в існуючий плейлист
<a id="sec09b"></a>
Плейлисти завантажуються тільки після натискання «Вибрати існуючий плейлист». Є пошук за назвою. Натискання плитки вибирає ціль; довге натискання або ⋮ відкриває дії з плейлистом.

## Редагування та видалення існуючого плейлиста
<a id="sec09c"></a>
Для доступного власного плейлиста можна змінити назву/приватність або видалити його. Видалення — віддалена необоротна дія й має окреме підтвердження.

> **УВАГА**  
> Редагування та видалення існуючого плейлиста змінюють YouTube/YTM безпосередньо. Перед підтвердженням перевірте назву та акаунт.

## Duplicate check
<a id="sec09d"></a>
Перед додаванням до існуючого плейлиста YTM Імпортer порівнює точний `videoId`, а не назви. Показується: скільки вибрано, скільки вже є в playlist, скільки повторів усередині імпорту і скільки реально нових.

| Режим | Результат |
| --- | --- |
| Пропустити дублікати й додати | Записуються тільки нові `videoId`; дублікати залишаються локально позначеними як пропущені. |
| Додати все одно | Явна спроба записати всі вибрані треки, включно з повторними `videoId`. |
| Продовжити без перевірки | Доступно лише якщо перевірка дублікатів не вдалося завершити; користувач свідомо приймає ризик повторів. |

## Результат операції
<a id="sec09e"></a>
Фінальна модалка показує «Додано / Не додано / Дублікати / Помилки», а для проблемних треків — назви та причини. За наявності playlistId можна відкрити плейлист у YTM або скопіювати посилання.

> **Rate limit / квота pause**  
> Якщо YouTube тимчасово обмежив частоту запис-запитів або закінчилась квота, YTM Імпортer зберігає незавершену роботу в Черга. Автоматичного повтору немає.

# 10. Черга / Pending Черга
<a id="sec10"></a>
Черга містить незавершені пошук або запис операції, які можна явно продовжити. Вона з’являється при квота/обмеження частоти запитів/авторизації паузах або інших відновлюваних станах.

*Приклад detail запис-job у Черга: пауза через забагато запис-запитів, 0/3 додано, 3 очікують.*

## Типи завдань
<a id="sec10a"></a>
| Тип | Що зберігається |
| --- | --- |
| Пошук | Snapshot плейлиста та список треків, які ще очікують Пошук. |
| Запис | Ціль, прогрес додавання, remainingTracks, помилки, причина паузи та прив’язка до акаунта/каналу. |

## Дії
<a id="sec10b"></a>
- Продовжити / Продовжити пошук — єдина явна команда на відновлення роботи.
- Відкрити плейлист у YTM — якщо playlistId уже відомий.
- Видалити з черги — видаляє тільки локальне завдання; вже додані remote треки не видаляються.

> **Без автоматичного Продовження**  
> Перезапуск застосунку, відкриття Черга або поворот екрана не повинні самі продовжувати Пошук/запис.

# 11. Історія
<a id="sec11"></a>
Історія — довгостроковий локальний журнал операцій. У поточному UI один логічний плейлист показується однією карткою, а окремі операції залишаються доступними всередині групи.

*Приклад Історія detail для операції, призупиненої через ліміт API.*

## Пошук і фільтр
<a id="sec11a"></a>
Історія має текстовий пошук і семантичний фільтр. Вони працюють разом. У групі видно кількість операцій та дату останньої зміни.

## Що є в detail
<a id="sec11b"></a>
- Дата, джерело, тип destination і приватність.
- Результат операції та лічильники: додано, дублікати, пропущено, очікує, помилки, не знайдено.
- Заміни та проблемні треки.
- Акаунт/канал для віддаленої операцій.
- Остання помилка, якщо є.

## Швидкі дії Історія
<a id="sec11c"></a>
| Дія | Наслідок |
| --- | --- |
| Відкрити плейлист у YTM | Відкриває віддалений плейлист, якщо відомий ID. |
| Відновити як поточний плейлист | Локально робить цей знімок поточним. Пошук/запис не стартують автоматично. |
| Зберегти / Поділитися Проєкт YTM | Створює проєкт із даними конкретної Історія-операції. |
| Копіювати підсумок / журнал проблем | Копіює текст у буфер. |
| Видалити локальний запис | Видаляє лише Історія entry; YouTube/YTM плейлист не змінюється. |

> **Existing playlist import batch**  
> Якщо Історія стосується додавання до вже існуючого плейлиста, експортований Проєкт YTM міститиме треки цієї операції, а не повну стару віддаленої бібліотеку плейлиста.

# 12. Центр відновлення
<a id="sec12"></a>
*Центр відновлення не виконує recovery сам — він веде до конкретного власника стану.*

*Реальний Центр відновлення v1.4.55: actionable стани зверху, завершені з попередженням окремо.*

Центр відновлення збирає локально збережені незавершені або перервані стани з Черга, Сесія синхронізації і релевантної Історія. Відкриття екрана нічого не продовжує автоматично.

## Секції
<a id="sec12a"></a>
| Секція | Значення |
| --- | --- |
| Потребує уваги | Є явна наступна дія: відкрити Черга, Bulk session або Історія. |
| Завершено з попередженням | Операція термінальна, але результат частковий/із помилкою і його корисно переглянути. |
| Нічого незавершеного | Черга/Bulk/Історія не містять станів, що потребують дії. |

## Індикатор ⚠ N
<a id="sec12b"></a>
Головний екран показує компактний ⚠ N тільки коли є actionable записи. Після відкриття Центр відновлення поточний count вважається acknowledged; значок перестає “дихати” і знову приверне увагу, коли count зміниться.

# 13. Синхронізувати всі / Синхронізація всіх
<a id="sec13"></a>
Синхронізація всіх призначений для масового приведення локальної бібліотеки до YouTube/YTM. Це окремий керований сценарій: спочатку лише для читання попередній перегляд, потім створення durable сесії, і лише після окремого підтвердження — віддалений запис.

## У режимі лише читання Попередній перегляд
<a id="sec13a"></a>
Меню → «Синхронізувати всі». Попередній перегляд читає локальні плейлисти та remote знімок і класифікує їх, але нічого не змінює у YouTube Music.

| Стан | Значення |
| --- | --- |
| NEW / Новий | Потрібно створити віддалений плейлист. |
| LINKED / Пов’язано з YTM | Remote playlist уже відомий; можна доповнити. |
| ALREADY_SYNCED | Змін не потрібно. |
| NEEDS_SEARCH | Є треки без готового точний `videoId`. |
| PENDING | Для плейлиста вже існує незавершене завдання. |
| BLOCKED | Синхронізація зараз небезпечна/неможлива; потрібне ручне вирішення. |

У Попередній перегляд користувач бачить локальні треки, готовність, заплановане створення/додавання, причину, оцінку Пошук і окрему оцінку запис API units.

## Створення сесії
<a id="sec13b"></a>
Після підтвердження створюється локальний контрольна точка і свіжий лише для читання віддалений базовий стан. Навіть після цього запис не починається автоматично: сесія відкривається в стані готовності до явного запуску.

## Сесія синхронізації
<a id="sec13c"></a>
*Приклад Сесія синхронізації: частково завершено, контрольна точка збережено, віддалений базовий стан відомий.*

Сесія показує стан, кількість плейлистів у плані, створені плейлисти, додані/не додані треки, actionable попередження, контрольна точка, remote знімок і деталі помилок.

- Почати синхронізацію — явний старт віддалений запис.
- Продовжити — явне відновлення paused/interrupted сесії.
- Відкотити цю синхронізацію — точний відкат тільки тих mutation, які записані в ledger цієї сесії.
- Продовжити відкат — явне відновлення paused відкат.

## Rollback
<a id="sec13d"></a>
Rollback не шукає “схожі” плейлисти за назвою. Він використовує точний ledger сесії: додані playlistItemId/`videoId` і плейлисти, створені саме цією сесією. Раніше існуючі плейлисти та треки за назвою не видаляються.

> **Ключова гарантія**  
> Після перезапуску Синхронізація всіх або відкат не продовжуються автоматично. Користувач завжди бачить durable стан і запускає продовження сам.
