# 7. Пошук і перевірка
<a id="sec07"></a>
*Користувацькі стани треку, які можна зустріти на екрані перевірки та пов’язаних екранах.*

## План пошуку перед запуском
<a id="sec07a"></a>
Перед пошуком YTM Importer показує план: скільки треків у списку, скільки реально потребують пошуку, скільки вже є в кеші, скільки нових запитів `search.list` приблизно знадобиться та яка локальна оцінка доступної квоти.

> **Кеш пошуку економить квоту**  
> Трек із точним `videoId` або валідним кешованим результатом не повинен даремно витрачати новий `search.list`. Повторний пошук планує тільки те, що справді потребує пошуку.

## Фільтри перевірки
<a id="sec07b"></a>
| Фільтр | Що показує |
| --- | --- |
| Усі | Весь трекліст. |
| Перев. | Треки, які потребують ручної уваги. |
| Готові | Треки, готові до запису. |
| Пробл. | Не знайдено / помилка / інші проблемні стани. |

## Ручна перевірка одного треку
<a id="sec07c"></a>
На детальному екрані видно оригінальний рядок, автоматично знайдений результат або ручний вибір, а також список кандидатів. Для кандидата доступні «Використати» і «Відкрити YTM».

- Вставити YouTube / YTM URL — вручну задати потрібне відео; застосунок намагається отримати реальну назву та канал через API.
- Пропустити цей трек — залишити позицію в локальному списку, але не записувати її.
- Повторити пошук — повторно шукати тільки там, де це потрібно; точний `videoId` і кеш не повинні зайво витрачати квоту.

## Проєкт YTM з екрана перевірки
<a id="sec07d"></a>
Екран перевірки дозволяє зберегти або поділитися поточним Проєктом YTM. Це найкращий формат, якщо треба відкласти роботу й пізніше відкрити той самий список із уже перевіреними точними `videoId`.

# 8. Поточний плейлист
<a id="sec08"></a>
Центр поточного плейлиста відкривається з картки поточного плейлиста на головному екрані. Це локальний центр керування одним робочим списком.

| Дія | Що робить |
| --- | --- |
| Треки / перевірка | Відкриває екран перевірки з усіма фільтрами та ручним вибором. |
| Знайти / перевірити | Запускає план пошуку лише для потрібних треків. |
| Створити / додати в YTM | Переходить до вибору цільового плейлиста. |
| Проєкт YTM / експорт | Зберегти або поділитися поточним робочим проєктом. |
| Заміни / проблемні треки | Журнал ручних замін, пропусків, дублікатів, відсутніх збігів і помилок. |
| Відкрити в YouTube Music | Відкрити останній цільовий плейлист, якщо відомий ID. |
| Копіювати посилання | Скопіювати URL цільового YTM плейлиста. |

## Журнал замін
<a id="sec08a"></a>
Є короткий формат для TikTok/публікації та повний текстовий журнал. Для кожної позиції можна бачити оригінал, результат, канал, статус або помилку.

# 9. Створення або додавання в YTM
<a id="sec09"></a>
*Запис у YTM виконується після вибору цілі та перевірки дублікатів.*

## Створити новий плейлист
<a id="sec09a"></a>
Можна змінити назву перед створенням і вибрати приватність: Приватний, За посиланням або Публічний. Після явного підтвердження застосунок створює плейлист і додає готові треки.

## Додати в існуючий плейлист
<a id="sec09b"></a>
Плейлисти завантажуються тільки після натискання «Вибрати існуючий плейлист». Є пошук за назвою. Натискання плитки вибирає ціль; довге натискання або ⋮ відкриває дії з плейлистом.

## Редагування та видалення існуючого плейлиста
<a id="sec09c"></a>
Для доступного власного плейлиста можна змінити назву/приватність або видалити його. Видалення — віддалена необоротна дія й має окреме підтвердження.

> **УВАГА**  
> Редагування та видалення існуючого плейлиста змінюють YouTube/YTM безпосередньо. Перед підтвердженням перевірте назву та акаунт.

## Перевірка дублікатів
<a id="sec09d"></a>
Перед додаванням до існуючого плейлиста YTM Importer порівнює точний `videoId`, а не назви. Показується: скільки вибрано, скільки вже є в цільовому плейлисті, скільки повторів усередині імпорту і скільки реально нових.

| Режим | Результат |
| --- | --- |
| Пропустити дублікати й додати | Записуються тільки нові `videoId`; дублікати залишаються локально позначеними як пропущені. |
| Додати все одно | Явна спроба записати всі вибрані треки, включно з повторними `videoId`. |
| Продовжити без перевірки | Доступно лише якщо перевірку дублікатів не вдалося завершити; користувач свідомо приймає ризик повторів. |

## Результат операції
<a id="sec09e"></a>
Фінальна модалка показує «Додано / Не додано / Дублікати / Помилки», а для проблемних треків — назви та причини. За наявності ідентифікатора `playlistId` можна відкрити плейлист у YTM або скопіювати посилання.

> **Пауза через обмеження частоти запитів або квоту**  
> Якщо YouTube тимчасово обмежив частоту запитів на запис або закінчилась квота, YTM Importer зберігає незавершену роботу в Черзі. Автоматичного повтору немає.

# 10. Черга незавершених операцій
<a id="sec10"></a>
Черга містить незавершені операції пошуку або запису, які можна явно продовжити. Вона з’являється при паузах через квоту, обмеження частоти запитів, авторизацію або інші відновлювані стани.

*Приклад детального екрана завдання запису в Черзі: пауза через забагато запитів на запис, 0/3 додано, 3 очікують.*

## Типи завдань
<a id="sec10a"></a>
| Тип | Що зберігається |
| --- | --- |
| Пошук | Знімок плейлиста та список треків, які ще очікують пошуку. |
| Запис | Ціль, прогрес додавання, список треків, що залишилися (системне поле `remainingTracks`), помилки, причина паузи та прив’язка до акаунта/каналу. |

## Дії
<a id="sec10b"></a>
- Продовжити / Продовжити пошук — єдина явна команда на відновлення роботи.
- Відкрити плейлист у YTM — якщо ідентифікатор `playlistId` уже відомий.
- Видалити з черги — видаляє тільки локальне завдання; уже додані віддалені треки не видаляються.

> **Без автоматичного продовження**  
> Перезапуск застосунку, відкриття Черги або поворот екрана не повинні самі продовжувати пошук/запис.

# 11. Історія
<a id="sec11"></a>
Історія — довгостроковий локальний журнал операцій. У поточному інтерфейсі один логічний плейлист показується однією карткою, а окремі операції залишаються доступними всередині групи.

*Приклад детального екрана Історії для операції, призупиненої через ліміт API.*

## Пошук і фільтр
<a id="sec11a"></a>
Історія має текстовий пошук і семантичний фільтр. Вони працюють разом. У групі видно кількість операцій та дату останньої зміни.

## Що є на детальному екрані
<a id="sec11b"></a>
- Дата, джерело, тип призначення і приватність.
- Результат операції та лічильники: додано, дублікати, пропущено, очікує, помилки, не знайдено.
- Заміни та проблемні треки.
- Акаунт/канал для віддалених операцій.
- Остання помилка, якщо є.

## Швидкі дії Історії
<a id="sec11c"></a>
| Дія | Наслідок |
| --- | --- |
| Відкрити плейлист у YTM | Відкриває віддалений плейлист, якщо відомий ID. |
| Відновити як поточний плейлист | Локально робить цей знімок поточним. Пошук і запис не стартують автоматично. |
| Зберегти / Поділитися Проєктом YTM | Створює проєкт із даними конкретної операції Історії. |
| Копіювати підсумок / журнал проблем | Копіює текст у буфер. |
| Видалити локальний запис | Видаляє лише запис Історії; плейлист YouTube/YTM не змінюється. |

> **Пакет додавання до існуючого плейлиста**  
> Якщо Історія стосується додавання до вже існуючого плейлиста, експортований Проєкт YTM міститиме треки цієї операції, а не повну стару віддалену бібліотеку плейлиста.

# 12. Центр відновлення
<a id="sec12"></a>
*Центр відновлення сам нічого не відновлює — він веде до конкретного екрана, який володіє цим станом.*

*Реальний Центр відновлення v1.4.55: стани, що потребують дії, зверху; завершені з попередженням — окремо.*

Центр відновлення збирає локально збережені незавершені або перервані стани з Черги, Сесії синхронізації та релевантних записів Історії. Відкриття екрана нічого не продовжує автоматично.

## Секції
<a id="sec12a"></a>
| Секція | Значення |
| --- | --- |
| Потребує уваги | Є явна наступна дія: відкрити Чергу, Сесію синхронізації або Історію. |
| Завершено з попередженням | Операція термінальна, але результат частковий/із помилкою і його корисно переглянути. |
| Нічого незавершеного | Черга, Сесія синхронізації та Історія не містять станів, що потребують дії. |

## Індикатор ⚠ N
<a id="sec12b"></a>
Головний екран показує компактний ⚠ N лише коли є записи, що потребують дії. Після відкриття Центру відновлення поточна кількість вважається переглянутою; значок перестає «дихати» і знову приверне увагу, коли кількість зміниться.

# 13. Синхронізація всіх плейлистів
<a id="sec13"></a>
«Синхронізація всіх» призначена для масового приведення локальної бібліотеки до стану YouTube/YTM. Це окремий керований сценарій: спочатку попередній перегляд лише для читання, потім створення збереженої сесії, і лише після окремого підтвердження — віддалений запис.

## Попередній перегляд лише для читання
<a id="sec13a"></a>
Меню → «Синхронізувати всі». Попередній перегляд читає локальні плейлисти та віддалений знімок і класифікує їх, але нічого не змінює у YouTube Music.

| Стан | Значення |
| --- | --- |
| Новий (`NEW`) | Потрібно створити віддалений плейлист. |
| Пов’язано з YTM (`LINKED`) | Віддалений плейлист уже відомий; його можна доповнити. |
| Уже синхронізовано (`ALREADY_SYNCED`) | Змін не потрібно. |
| Потрібен пошук (`NEEDS_SEARCH`) | Є треки без готового точного `videoId`. |
| Є незавершене завдання (`PENDING`) | Для плейлиста вже існує незавершене завдання. |
| Заблоковано (`BLOCKED`) | Синхронізація зараз небезпечна/неможлива; потрібне ручне вирішення. |

У попередньому перегляді користувач бачить локальні треки, готовність, заплановане створення/додавання, причину, оцінку пошуку та окрему оцінку одиниць API для запису.

## Створення сесії
<a id="sec13b"></a>
Після підтвердження створюється локальна контрольна точка та свіжий віддалений базовий стан, прочитаний без змін. Навіть після цього запис не починається автоматично: сесія відкривається в стані готовності до явного запуску.

## Сесія синхронізації
<a id="sec13c"></a>
*Приклад Сесії синхронізації: частково завершено, контрольну точку збережено, віддалений базовий стан відомий.*

Сесія показує стан, кількість плейлистів у плані, створені плейлисти, додані/не додані треки, попередження, контрольну точку, віддалений знімок і деталі помилок.

- Почати синхронізацію — явний старт віддаленого запису.
- Продовжити — явне відновлення призупиненої/перерваної сесії.
- Відкотити цю синхронізацію — точний відкат тільки тих змін, які записані в журналі змін цієї сесії.
- Продовжити відкат — явне продовження призупиненого відкату.

## Відкат
<a id="sec13d"></a>
Відкат не шукає “схожі” плейлисти за назвою. Він використовує точний журнал змін сесії: додані ідентифікатори `playlistItemId` / `videoId` і плейлисти, створені саме цією сесією. Раніше існуючі плейлисти та треки за назвою не видаляються.

> **Ключова гарантія**  
> Після перезапуску «Синхронізація всіх» або відкат не продовжуються автоматично. Користувач завжди бачить збережений стан і запускає продовження сам.
