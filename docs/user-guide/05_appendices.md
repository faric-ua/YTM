# A. Додаток: типи файлів YTM Importer
<a id="secA"></a>
| Тип | Типова назва / структура | Для чого |
| --- | --- | --- |
| Повна локальна резервна копія | `YTM_Backup_*.json`; `format=ytm-importer-local-backup` | Повне локальне відновлення Історії, Черги, робочого простору та кешів без відкату квоти. |
| Резервна копія історії | `YTM_History_*.json`; JSON-масив записів Історії | Відновити тільки Історію. |
| Діагностика Черги | `YTM_Pending_*.json`; масив завдань Черги | Технічний експорт Черги, не повна резервна копія. |
| Проєкт YTM | `*.ytm-project.json`; `format=ytm-importer-playlist-project` | Переносний проєкт одного плейлиста з точними `videoId`. |
| Резервна копія бібліотеки акаунта | Папка + `manifest.json` + Проєкти YTM | Архів/резервна копія віддаленої бібліотеки акаунта. |
| Діагностика TXT | Текстовий файл | Підтримка/діагностика без токена OAuth; ідентифікатори маскуються. |

> **Тип файла визначається вмістом**  
> Актуальний контракт бібліотеки файлів не покладається лише на розширення `.json` або префікс назви. Перед відновленням зі зміною даних остаточну перевірку все одно виконує власник формату.

# B. Додаток: актуальний стан документації
<a id="secB"></a>
Цей документ згенеровано для YTM Importer v1.4.55 зі стану гілки feat/v1.4.55-ux-hardening. Знімок вихідного коду під час формування: 47a14443bafa93dcef7fd930a394c435e6098f36.

Окрему перевірку Центру відновлення на телефоні завершено на підписаному кандидатові з вихідним кодом `efab5dc15ce389aa50e5d9d15aa1cdd78e60e08f`, номер збірки `37338681198`. Після цього в гілці продовжилася робота #54 над бібліотекою файлів; тому частина нового файлового інтерфейсу може бути новішою за APK, встановлений під час тесту Центру відновлення.

## Як розширювати документ надалі
<a id="secB1"></a>
- Додавати нову функцію в тематичний розділ, а не тільки в історії змін.
- Якщо з’явився новий екран — додати його до змісту та сценаріїв.
- Якщо змінився небезпечний сценарій роботи (Відновлення/Видалення/Запис/Відкат) — оновити також інформаційний блок з наслідками.
- Для нових форматів файлів — оновити Додаток A та розділ 16.
- Після великої зміни оновити знімок вихідного коду і дату документа.

> Канонічну текстову версію доцільно зберігати в репозиторії в docs/user-guide/. DOCX — редагована книжкова версія для користувача; Markdown — текстове джерело, яке простіше редагувати й версіонувати.
