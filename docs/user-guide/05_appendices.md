# A. Додаток: типи файлів YTM Імпортer
<a id="secA"></a>
| Тип | Типова назва / структура | Для чого |
| --- | --- | --- |
| Full Local «Назад»up | YTM_«Назад»up_*.json; format=ytm-importer-local-резервна копія | Повне локальне відновлення Історія/Черга/робочий простір/caches без відкат квота. |
| Історія «Назад»up | YTM_Історія_*.json; масив записів Історії | Відновити тільки Історія. |
| Pending Діагностика | YTM_Pending_*.json; масив завдання в Черзіs | Технічний експорт Черга, не повне відновлення. |
| Проєкт YTM | *.ytm-project.json; format=ytm-importer-playlist-project | Переносний проєкт одного плейлиста з точний `videoId`. |
| Account Library «Назад»up | Папка + `manifest.json` + Проєкт YTM | Архів/резервна копія віддаленої бібліотеки акаунта. |
| Діагностика TXT | текстовий файл | Підтримка/діагностика без токен OAuth; ідентифікатори маскуються. |

> **Тип файла визначається вмістом**  
> Актуальний бібліотека файлів контракт не покладається лише на розширення .json або префікс назви. Для відновлення зі зміною даних остаточну перевірку все одно виконує власник формату перед будь-якою мутацією.

# B. Додаток: актуальний стан документації
<a id="secB"></a>
Цей документ згенеровано для YTM Імпортer v1.4.55 зі стану гілки feat/v1.4.55-ux-hardening. Знімок вихідного коду під час формування: 47a14443bafa93dcef7fd930a394c435e6098f36.

Окремий перевірка Центру відновлення на телефоні закрито на вихідний код підписаного кандидата efab5dc15ce389aa50e5d9d15aa1cdd78e60e08f, run 37338681198. Після цього в гілці продовжилася #54 бібліотека файлів робота; тому частина нового файлового UX може бути новішою за APK, який був встановлений під час Центр відновлення тесту.

## Як розширювати документ надалі
<a id="secB1"></a>
- Додавати нову функцію в тематичний розділ, а не тільки в історія змін.
- Якщо з’явився новий екран — додати його до змісту та сценаріїв.
- Якщо змінився небезпечний сценарій (Restore/Delete/Write/Rollback) — оновити також інформаційний блок з наслідками.
- Для нових форматів файлів — оновити Додаток A та розділ 16.
- Після великої зміни оновити знімок вихідного коду і дату документа.

> **Живий документ**  
> Канонічну текстову версію доцільно зберігати в репозиторії в docs/user-guide/. DOCX — читабельний артефакт для користувача; джерело Markdown простіше редагувати й версіонувати.
